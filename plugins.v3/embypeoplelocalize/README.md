## 一、这个插件是干什么的

用大模型（LLM）把 Emby 里的**演职人员名字**（演员 / 声优 / 导演 / 编剧 / 制片）与**角色名**翻译成规范的简体中文，并写回媒体库的 `nfo` 文件，让 Emby 显示中文名单。

与「只翻译一次」的脚本不同，它是**一套带账本、可对账、可回滚**的流水线：

- **只认本地 nfo 文件**：直接读写 `tvshow.nfo` / `movie.nfo` / `episode.nfo`，不依赖 Emby 刮削写回接口（省请求、也不怕 Emby 重刮覆盖）。
- **翻译记录入库**：每条「原文名 → 译文名」都记账，翻译完 ≠ 落盘完，可随时查、可回滚重来。
- **人名池全局复用**：同一个人名（无论出现在多少部作品里）只翻一次，之后全局复用，几乎不重复消耗 AI 额度。
- **失效不误删**：媒体库里的目录/集被删掉后先进**观察期**（默认 24 小时，可调），期间重新入库会自动恢复，超期才判定为真删除。
- **限流/熔断友好**：请求间隔、TPM 预算、限速熔断、失败清单重试，AI 额度不会被烧光，也不会因为一次 429 就整批失败。

支持的翻译类型：

| 位置 | 说明 |
|---|---|
| **第一排（人物姓名）** | 演员 / 声优 / 导演 / 编剧 / 制片等人名 |
| **第二排（角色名）** | 人物饰演的角色名，如 `Jiro Yakuin (voice)` → `药院次郎` |

## 二、运行原理与四条工作链路

插件共有 **四条** 会把内容送进「翻译流水线」的入口，它们**互不重复**——同一个人名先被哪个入口翻到，另一个入口都会命中已有译文，不会重复调 AI。

| # | 入口 | 触发方式 | 对应设置开关 |
|---|---|---|---|
| 1 | **Webhook 入库** | Emby 有新入库事件时推送 | 设置 → 基础设置 → `Webhook 入库后自动翻译` |
| 2 | **NFO 扫描 / 探测库入库** | 手动点「NFO 扫描 / 续跑 / 探测库」，或定时任务 | 设置 → 基础设置 → `扫描 / 探测库入库后自动翻译` |
| 3 | **拉取人名** | 人名池页「拉取人名」（把 Emby 的 Person 拉进人名池） | 设置 → 人名池 → `自动翻译新拉取的人名` |
| 4 | **人工修改** | 在库页/人名池页点铅笔改译文 | 无需开关（人工修正优先级最高，AI 不会覆盖） |

### 完整流水线

```
① 采集     读取 nfo / Emby，把「原文名 + 角色」记录进插件数据库（这一步永远执行，与翻译开关无关）
② 去重     命中人名池 / 已有译文 / 繁转简 → 直接得到译文（不调 AI）
③ 翻译     剩余词条交后台常驻翻译 Worker 调 LLM（受限流、TPM 预算、分批策略约束）
④ 写回     把译好的名单写进 nfo 文件（`tvshow.nfo` + 各集 `episode.nfo`）
```

**重要概念：采集 ≠ 翻译 ≠ 写回**，三者互相独立：

- 关掉 AI 翻译，**采集照常**（原文仍会入库，库页能看到、能手动改）。
- 「翻译范围」只决定**翻译什么**，不决定采集什么。
- 翻译完成后若「自动写回」关闭，需要去库页点「全部写回」才落盘。

### 三条互补的「发现新内容」通道

> 通道是 **3 条**，**触发方式**有 3 种：**手动**（仪表盘点按钮）、**定时**（设置页的两个定时开关）、**事件推送**（Emby Webhook）。
> 「定时」本身**不是第 4 条通道** —— 它是给「NFO 扫描」和「探测库」加**自动触发**：`定时全量扫库` 定时跑扫描，`探测库`（设置项）定时跑探测对账。

| 通道 | 触发方式 | 管什么 | 不查什么 |
|---|---|---|---|
| **NFO 扫描** | 手动：仪表盘 `NFO 扫描` / `续跑`<br>定时：设置页 `定时全量扫库` + `扫库间隔（小时）` | 本地文件系统里的 nfo（全量 / 断点续扫增量） | 不查 Emby 清单 |
| **探测库** | 手动：仪表盘 `探测库`<br>定时：设置页 `探测库` + `探测间隔（分钟）` | 与 Emby 清单**双向对账**：Emby 有而插件没有的补翻；插件有而 Emby 已没有的标「待恢复」 | — |
| **Webhook** | 事件推送：Emby 入库时实时推送 | Emby 主动推的入库事件（实时） | 关插件期间的漏事件，靠上面两条（尤其它们的**定时**）兜底 |

## 三、安装与前置条件

1. 在 MoviePilot 插件市场添加本仓库地址，搜索「Emby 演职人员中文化」安装（V3 版）。
2. 确保 MoviePilot 已配置 **LLM**（系统设置 → 大模型配置），或稍后在插件设置页里填「插件配置」。
   - 可去仪表盘「依赖」灯里点开「运行依赖」看 LLM 是否就绪。
3. 打开插件 → **设置** 页：
   - 打开 `启用插件`；
   - 在「NFO / 扫描」里勾选要处理的**媒体库**，必要时配置「路径映射」；
   - 按需打开 `Webhook 入库后自动翻译` / `扫描·探测库入库后自动翻译`；
   - 点 `测试连接` 验证 LLM 可用，最后 `保存配置`。
4. 回到 **仪表盘** 点「NFO 扫描」跑一次全量，或去 **库** 页手动翻译。

**依赖说明**（仪表盘「依赖」灯可查）：

| 依赖 | 缺失影响 |
|---|---|
| `zhconv`（繁简转换） | 繁体人名/角色名自动转简体失效，繁体将直接走 LLM |
| `httpx` | LLM 调用降级为 requests，兼容性下降 |
| `openai` SDK | 自动降级为 requests，功能可用 |
| LLM 配置（系统或插件） | 无法翻译 |

## 四、页面结构

插件页面共 **4 个子页面**（桌面左侧竖排导航；移动端顶部「当前页 + 下拉箭头」按钮 → 底部抽屉「切换页面」）：

| 页面 | 图标 | 作用 |
|---|---|---|
| **仪表盘** | `mdi-view-dashboard-outline` | 状态灯、运行操作（扫描/续跑/探测/拉取/暂停/继续/终止）、统计、日志、Webhook 事件 |
| **库** | `mdi-library` | 已入库条目清单 + 翻译前后名单 + 单条翻译/写回/重拉 + 人工编辑 |
| **人名池** | `mdi-account-search` | Emby Person 总仓库：拉取、翻译、同步回 Emby |
| **设置** | `mdi-cog-outline` | 全部配置项 |

- 页面标题：**演职人员中文化**（副标题 `Emby People Localize`），右上角 `关闭插件`（`mdi-close`）。
- 插件未启用时：除「设置」外所有页面会盖一层遮罩 **插件已停用 / 插件已被关闭，其他页面暂不可用 / [前往设置启用]**；在设置页则顶部显示横幅 **插件未启用：请先在设置页打开「插件总开关」并保存。**

### 通用拦截机制（插件内部一致行为）

1. **插件未启用**：所有会改数据/起任务的按钮都会提示 `插件未启用：请先在设置页打开「启用插件」`（后端也会拒绝，不是只在前端拦）。
2. **任务进行中**：会修改数据库或文件的操作，点击时会弹出拦截弹窗：

   > **任务正在执行，修改已锁定**
   > 当前正在进行：`AI 翻译`（任务类别，多类用 ` / ` 连接）
   > 任务状态：`AI 翻译中`（数据变更已锁定）
   > 本次尝试的操作：`全部翻译`
   > 该操作会修改数据库或文件。为避免翻译结果、写回内容或人工修改互相覆盖，当前暂不可执行。请等待任务完成，或到仪表盘「终止」后再试。
   > 按钮：`查看任务`（跳到仪表盘）/ `取消`
   >
   > **不提供「强行继续」**。

   任务状态中文映射：`空闲 / NFO 扫描中 / 探测库中 / AI 翻译中 / 写回 NFO 中 / 拉取人名中 / 人名池同步中 / 正在停止`。

   > 例外：**停止 / 暂停 / 继续 / 导出 / 清空日志 不受拦截**（安全控制与只读操作）。

3. **二次确认**：删除、清空、全库改名等破坏性操作都会弹确认框（标题 + 正文 + 详情 + `取消` / 确认按钮）。

## 五、仪表盘

数据 **每 5 秒自动刷新**（每个请求 15 秒超时保护）；切页/切回前台时也会立即刷新。

### 5.1 顶部状态灯

| 灯 | 显示 | 颜色含义 | 点击 |
|---|---|---|---|
| **服务** | 无任务 = `空闲`；有任务 = `扫描中 / 翻译中 / 写回中 / 拉取人名中 / 探测库中`（多任务 ` + ` 连接） | 绿=有任务、灰=空闲 | — |
| **数据库** | `正常` / `异常` | 绿 / 红 | — |
| **依赖** | `正常` / `异常` / `检测中…` | 绿 / 红 | ✅ 打开「运行依赖」弹窗 |
| **Webhook** | `● 已开启` / `○ 已关闭`；开启且出错时附 `异常`（红）；有待配置事件时附 `待配置 N` | 灰=关闭、绿=正常、红=异常 | — |
| **LLM** | `正常` / `限速 Ns` / `限速` `配额不足` `认证失败` `上下文过长` `服务异常` `网络异常` `空响应` | 绿=正常；橙=可自愈类（限速/服务异常/网络异常/空响应）；红=需人工介入（配额不足/认证失败/上下文过长） | — |
| **AI 翻译 Worker** | 离线 = `离线`；在线 = `在线 · 待命 / 正在翻译 / 已暂停（手动）/ 限流暂停 / 认证暂停 / 配额暂停` | 绿=待命；橙=正在翻译/限流暂停/手动暂停；红=离线/认证暂停/配额暂停 | — |

- Worker 灯附加小字（三选一）：`剩余约 N 分钟`（暂停中）/ `目标 {范围} · {done}/{total}`（正在翻译）/ `待翻译 {pending}`。
- 状态灯右侧还会显示当前阶段进度（三选一）：`拉取人名 x/y`、`探测库中…`（或当前标题）、`{扫描标题}（x/y · n%）`。

**Webhook 关闭提醒条**（Webhook 关闭时出现）：

> **Webhook 已关闭：新入库事件不会接收。NFO 扫描 / 探测库仍可发现新条目。**
> 已有挂起事件：N（关闭期间冻结不丢失，重新开启后自动续跑）
> [继续处理待配置事件]（有待配置事件时出现）

### 5.2 运行操作

| 按钮 | 作用 | 触发接口 | 二次确认 |
|---|---|---|---|
| **NFO 扫描** | 扫描已勾选媒体库目录下的本地 nfo：采集入库 → 翻译 → 写回（有断点则跳过已处理继续扫，否则全量）。**只管本地文件，不查 Emby 清单——查 Emby 用「探测库」** | `POST /scan` | 无 |
| **续跑** | 继续上次未完成的扫描（跳过已处理文件）。预览模式开启时只入库不写文件 | `POST /translate_all` | 无 |
| **探测库** | 立即跑一轮探测：Emby 缺的集/新条目补翻，Emby 已删的集标「待恢复」 | `POST /probe/run` | 无 |
| **拉取人名** / `拉取中 x/…` | 把 Emby 的 Person 拉进人名池（翻译一次全局复用）：按设置页「翻译范围」的人名类型开关拉取；拉取期间入库事件自动排队 | `POST /pool/fetch` | 无 |
| **暂停** | 暂停正在运行的任务（扫描 / 拉取人名 / AI 翻译）：进度与词条都保留；翻译会等当前一批完成后停 | `POST /task/pause {target:'all'}` | 无 |
| **继续** | 继续之前暂停的任务 | `POST /task/resume {target:'all'}` | 无 |
| **终止** | 立即中断扫描/拉取人名/AI 翻译/写回；断点保留可续跑 | `POST /stop` | **有** |

- 「暂停」与「继续」互斥显示（有任务被暂停时显示「继续」）。
- 「续跑」在无有效断点时置灰，悬停提示：**没有可续跑的断点（上轮已正常跑完，或配置变更使断点作废）—— 需要全量处理请点「NFO 扫描」；扫描中途点「终止」后，这里就能续跑**。
- 插件未启用时，操作区右侧显示：`插件未启用，操作已锁定`。

**「终止」的二次确认：**

> **终止当前任务**
> 终止后将立即中断正在运行的扫描 / 拉取人名 / AI 翻译 / 写回任务；已处理的进度与断点保留，之后可点「续跑」或重新发起。
> 详情：AI 翻译会立即停止（不再发起新请求）；已翻译入库的内容不受影响。
> 按钮：`取消` / `终止`（红）

### 5.3 「运行依赖」弹窗

点状态灯「依赖」打开。标题 `运行依赖`，右上 `重新检测`（`GET /deps/check`）。

每项显示图标（✅ 正常 / ❌ 缺失）、名称、状态 chip（`正常` / `未安装`）、说明；底部提示：**依赖由 MoviePilot 安装插件时按 requirements.txt 自动安装；缺失时功能降级（见各项说明）。**

### 5.4 阶段进度卡

逐行显示四个阶段（有运行时）：**NFO 扫描**（蓝）/ **拉取人名**（青）/ **AI 翻译**（紫）/ **NFO 写回**（teal），每行 = 名称 + 进度条 + `done / total · 当前项标题`。

无任务时占位：**当前没有运行中的阶段任务（扫描 → 翻译 → 写回 自动衔接；终止互不影响）**

### 5.5 统计卡片（4 张）

| 卡片 | 数值 | 副标题 | 来源 |
|---|---|---|---|
| **库中条目** | 已入库作品数 | 已采集入库的作品数 | `GET /db/stats`（按 `item_id` 去重，排除观察期行） |
| **池命中率** | N% | 池/繁简命中不调 AI 的比例 | `GET /status` |
| **人名池** | 池内总人数 | `待翻 N · 待同步 N` | `GET /status` |
| **Webhook 已处理** | 累计处理事件数 | 入库事件自动翻译计数 | `GET /status` |

### 5.6 翻译失败词条卡（仅有失败时出现）

标题 **翻译失败词条**（红字 + 数量 chip），逐条列出词条名与失败原因。

| 按钮 | 作用 | 接口 | 二次确认 |
|---|---|---|---|
| **重试失败项** | 把失败词条重新交后台翻译，成功后自动移出清单 | `POST /translate/retry_failed` | 无 |
| **清空** | 清空失败清单（不再自动重试，下次扫描会再尝试） | `POST /translate/clear_failed` | **有** |

**「清空」确认：** 标题 `清空失败清单` / 正文 `确认清空失败清单（N 个词条）？` / 详情 `清空后这些词条不再出现在「翻译失败词条」里，不会自动重试（下次扫描会重新尝试翻译）。` / 确认按钮 `清空`（红）。

### 5.7 实时日志卡

标题 **实时日志**，右上 `刷新` 与 `清空`。逐行显示「时间 + 级别 chip（INFO/WARNING/ERROR）+ 消息」，固定高度可滚动（后端缓冲上限 500 条）。

- 无日志占位：**暂无日志** / *启动/扫描/保存配置等操作后会在此滚动显示*
- `清空` → 确认框 `清空运行日志`：正文 `确认清空插件日志缓冲？`，详情 `仅清空插件的日志显示（不影响已写回的 nfo 与翻译记录）；清空后无法恢复。`，按钮 `清空`（橙）。清空不受插件停用限制。

### 5.8 Webhook 最近事件卡

标题 **Webhook 最近事件**，标题行有：
- `待配置 N` chip（有待配置事件时）
- 统计 chip：`收 {总} / 成 {成功} / 败 {失败}`
- 最近错误 chip（红，显示错误前 40 字）
- `刷新`、`清空`（清空有二次确认，仅清状态非「待恢复」的事件）

**待配置提醒条**（有待配置事件时）：

> **有 N 个入库事件因目录映射不命中而挂起（待配置）。请到设置页确认已选择该媒体库（必要时调整「路径前缀替换」）后，再点「继续处理」自动翻译；不想处理可点「放弃全部」。**
> [继续处理] → `POST /webhook/pending_continue`
> [放弃全部] → 确认框 `放弃全部待配置事件`（正文 `确认放弃全部 N 个待配置（挂起）事件？`，确认按钮 `放弃`（橙））→ `POST /webhook/pending_clear`

两列内容：

**左列「入库事件」**（状态 ≠ 待恢复）：时间 + 名称 + 集号 + 状态 chip + 消息。状态 chip 含义：

| chip | 含义 |
|---|---|
| `完成` | 已入库（并按设置决定是否已翻译） |
| `失败` | 入库或翻译失败 |
| `跳过` | 过滤后无需处理 |
| `待配置` | 目录映射不命中，挂起等配置 |
| `待恢复` | 条目失效，观察期等待重新入库 |
| `需确认` | 状态无法确认（如 Emby 查询失败），需人工判断 |
| `处理中` | 正在处理 |
| `已接收` | 已收到，等待延迟后处理 |

**右列「失效 / 待恢复」**（含 `清除` 按钮）：逐条显示名称 + `到期 MM-DD HH:mm` chip + 消息。

- 空占位：**暂无失效记录** / *nfo 目录消失后会出现在这里（观察期，到期自动检查）*
- `清除` → 确认框 `立即清除全部失效记录`：正文 `确认立即清除全部失效记录（N 条）？这些条目的翻译记录将被删除（人名池保留），不再等待观察期。`，详情 **注意：若条目正在重新下载/洗版，清除后重新入库会当作全新条目重新翻译（重复消耗 AI 额度）。**，确认按钮 `清除`（红）。

「库」= 插件数据库里已采集的条目清单 + 每个条目的翻译前后名单。左右两栏，**每 8 秒轮询刷新**，右栏详情另有 30 秒静默刷新。

### 6.1 顶部工具条

### 6.2 左栏：条目列表

- **搜索框**：占位符 `搜索剧集 / 电影标题…`（纯前端过滤，不请求后端）。
- **类型筛选**：`全部` / `剧集` / `电影`（纯前端过滤）。
- **分组**：按媒体库分组（未选库的归 `未分类`），可展开/收起，右侧显示条目数。
- **条目行**：前缀图标（剧集 `mdi-television-classic` / 电影 `mdi-movie-outline`，**不加载海报**以免滚动卡顿）+ 标题 + 副标题 `{类型} · {N} 人[ · {M} 集]`。
  - 失效标记：整条失效 → 红底 + `待恢复` chip；部分集失效 → 黄底 + `{N} 集待恢复` chip（悬停：*部分集被服务器删除，观察期内重新入库自动恢复；超期自动清理（不会一直显示）*）。

### 6.3 右栏：条目详情

| 按钮 | 作用 | 接口 |
|---|---|---|

| **写入** / **恢复到 Emby** | 把当前条目已翻译名单写回 nfo（第一排同时写入服务器）。`server_id` 为空的本地条目显示「写入」，Emby 条目显示「恢复到 Emby」 | `POST /db/restore` |

> 按「原文名」汇总；点「N 处 ▾」展开出现清单可逐处编辑；铅笔（汇总行）= 全库同名改（弹窗里确认数量）；出现清单里的铅笔可选「仅这一处 / 该剧所有集 / 全库同名」。

**剧集条目**显示两个区块：

1. **主演员**（来自 `tvshow.nfo`，提示 `（来自 tvshow.nfo · 编辑时在弹窗里选范围）`）：按类型分段（演员 / 声优 / 客串 / 导演 / 编剧 / 制片 / 作曲 / 摄影 / 剪辑），每段带图标 + 类型名 + 数量（只有一种类型时不显示段标题）。每人 = `主名` + `饰 角色` + 铅笔。

**「清除该剧角色记忆」确认：** 标题 `清除该剧角色翻译记忆` / 正文 `清除「{剧名}」的第二排角色翻译记忆？` / 详情 `清除后该剧各集的角色名需要重新翻译（重新消耗 AI）。注意：删除/恢复/清空翻译记录都不会清记忆，只有这里会。` / 确认按钮 `清除`（红）。

## 七、人名池

人名池 = **Emby Person 的总仓库**。核心价值：同一个人名全局只翻一次，之后出现在任何作品里都直接复用。

**每 3 秒自动刷新**统计与进度。

### 7.1 顶部统计（一行文字）

```
共 N 人 · 待翻 N · 待同步 N · 已同步 N（其中原文已是中文 N）
```

| 片段 | 含义 |
|---|---|
| `共 N 人` | 池内 Person 总数 |
| `待翻 N` | 还没有有效译文、且原文也不是中文 |
| `待同步 N` | 已有目标名，但 Emby 里的当前名 ≠ 目标名（等着写回 Emby） |
| `已同步 N` | Emby 当前名 == 目标名 |
| `（其中原文已是中文 N）` | 无需操作（不用翻也不用同步） |

### 7.2 操作按钮

| 按钮 | 作用 | 接口 | 二次确认 |
|---|---|---|---|
| **拉取人名** | 打开「拉取人名」弹窗，从 Emby 拉 Person 入池 | `POST /pool/fetch` | 无 |
| **批量翻译** | 打开「批量翻译」弹窗（无待翻时提示 `没有待翻译的人名`） | `POST /pool/translate` | 无 |
| **批量同步** | 打开「批量同步到 Emby」弹窗（无待同步时提示 `没有待同步的人名`） | `POST /pool/sync` | 无 |
| **清除人名池** | 清空整个人名池 | `POST /pool/clear` | **两级确认** |
| **导出** | 导出池为 JSON（文件名 `embypeople_pool_<时间戳>.json`） | `GET /pool/export` | 无 |
| **导入** | 从 JSON 导入池（文件 ≤30MB、≤50000 条） | `POST /pool/import` | 无 |

**「清除人名池」两级确认：**
1. 标题 `清除人名池` / 正文 `确认清除人名池全部 N 人？` / 详情 `将删除人名池里的全部条目（原文名 / 译名 / 来源标记）。此操作不可恢复，建议先「导出」备份。` / 按钮 `取消` / `继续`（红）
2. 标题 `再次确认` / 正文 `确定要清空整个人名池吗？` / 详情 `⚠️ 人工修正的译名也会一并删除，且无法恢复。清除后可重新「拉取人名」→「批量翻译」重建。` / 按钮 `取消` / `确认清除`（红）

### 7.3 进度条（条件显示）

**拉取进度**：`已拉取 x / y · 当前项`；结束后显示 `上次拉取：新增 N · 更新 N · 无变化 N · 过滤 N · 失败 N`。按钮 `暂停` / `继续`（`POST /task/pause|resume {target:'pool'}`）。

**翻译进度**：`AI 翻译中（范围）· x/y · 当前项`；暂停时 `⏸ 翻译已暂停（手动）`。按钮 `暂停` / `继续`（`target:'translate'`）。

### 7.4 搜索与筛选

- **搜索框**：占位符 `搜索 原文 / 译名…`（匹配原文名 / 译名 / Emby 当前名）。
- **类型筛选**：`全部` / `演员` / `导演` / `编剧` / `制片` / `客串`
  > 注意：筛选按**原始类型**分类，但**类型的显示**会把 `Actor` / `VoiceActor` / `GuestStar` 统一显示为 **演员**（排在第一位），后面再接导演/编剧/制片等「特别身份」；完全没有类型信息的显示 `未分类`。所以筛「客串」出来的行，类型列仍会显示「演员」。
- **状态筛选**：`全部` / `待翻译` / `无需操作` / `待同步` / `已同步` / `同步失败`
- **重置**：清空关键词与筛选。

### 7.5 列表（桌面表格 / 移动卡片）

**桌面表格 6 列**：

| 列 | 内容 |
|---|---|
| `原文名` | 拉进来的原名（悬停显示 Emby 当前名） |
| `译名` | 只在**第一排改过**时显示最终译名，否则显示 `—` |
| `类型` | 见上（演员 / 导演 / 编剧 / 制片 / 未分类） |
| `状态` | 徽章，见下表 |
| `出现` | `查看` / `收起` → 展开该人名出现的作品清单（`《剧名》×N`，失效作品标 `待恢复`） |
| `操作` | `改`（打开编辑弹窗）/ `同步`（有可同步目标名时才显示，同样是打开编辑弹窗）/ `重拉`（从 Emby 重新拉取该人，刷新当前名/类型，legacy 行顺带补 Person ID） |

**状态徽章**：

| 徽章 | 何时出现 |
|---|---|
| 🔴 `待翻译` | 没有有效译文，原文也不是中文（含假名的日文名、英文名等）；或翻译被标记失败 |
| 🟩 `无需操作` | 原文本身就是中文（含汉字、无假名，如「角田 雄二郎」这类夹空格也算） |
| 🟡 `待同步` | 已有目标名但 Emby 当前名 ≠ 目标名（等待写回 Emby） |
| 🟢 `已同步` | Emby 当前名 == 目标名 |
| ⚠️ `同步失败` | 同步到 Emby 失败 |

> **原文名 / 译名两列的口径**：原文名列永远显示拉进来的原名；译名列**只在改过时才显示**最终译名，没改过一律 `—`（移动端更细：原文本身非中文时显示 `— 未译`）。这样既能看清「哪些改过」，人工改错时也能对照原文修正。

### 7.6 弹窗

**① 编辑人名**：`原文` / `Emby 当前` / `类型`（只读）+ `译名` 输入框（`留空 = 清除译文`）+ 复选 `同步到 Emby（改 Emby 演员名，全局生效；默认不改）`。

- 提示：`保存只改人名池（manual 最高优先级，AI 不覆盖）。勾选上方选项后保存会同时改 Emby Person 实体名（全局生效）。`
- 只保存 → 提示 `已保存池译文（未同步 Emby）`，并同步回写「库」第一排的全库同名记录。
- 勾选后保存 → 先存池再同步 Emby，成功提示 `已同步到 Emby`。

**② 拉取人名**：

- 提示：`拉取类型跟随设置页「翻译范围」的人名类型开关（不再单独设置）。人物类型优先从 Emby People 关系获取；无法确定类型的全库 Person 不参与按类型筛选，建议使用「已选媒体库」范围。`
- 单选：`仅已选媒体库中的 Person（推荐，快）` / `全库 Person（/Persons 全量，慢）`
- 按钮：`取消` / `按当前设置重筛池` / `开始拉取`

**③ 批量翻译**：显示 `待翻译 N 个` / `无需操作 N 个` + 复选 `翻译完成后自动同步 Emby（默认关闭）`；提示 `翻译由后台常驻 worker 自动完成（限流不丢）；不勾则只写池，之后到「人名池 → 批量同步」手动同步。`；按钮 `取消` / `开始`。

**④ 批量同步到 Emby**：显示 `待同步 N 个` + 警告 `⚠️ Emby 里改名会全局生效（该 Person 在所有作品中的显示名都会变）。`；按钮 `取消` / `开始`。

### 8.2 NFO / 扫描

**分区：媒体库扫描范围**

  - 按钮 `测试`（单库路径预检）、`浏览`（只读文件浏览）

**分区：路径映射（Emby Path → 本机 MP 路径）**

- 说明：每台服务器各一行；未配置的服务器直接使用 Emby 原路径。

**② 翻哪些类型 + 每个文件翻几个**

| 按钮 | 作用 | 接口 |
|---|---|---|
| **测试连接** | 真实调用一次 1 词翻译，检测 LLM 地址/密钥/模型是否可用（地址缺 `/v1` 会自动尝试），并把成功或具体错误类型（限流/配额/认证/上下文/服务端/网络/空响应）回显 | `POST /llm/test` |
| **保存配置** | 保存全部配置并热生效 | `POST /config` |

> 保存时的提示：常规情况提示 `配置已保存并生效`。若**当前有任务正在运行**，后端会返回「配置已保存。当前有任务正在运行 —— 与翻译范围 / 人数上限 / 写回策略相关的设置将在**下一个任务**生效（本任务继续使用启动时的快照）」，该说明会出现在**实时日志**里。

### 8.8 只读文件浏览弹窗（点路径 / 「浏览」打开）

标题 `浏览：{库名}`，副标题为当前路径，右上 chip `只读`。
按钮：`返回上级` / `刷新` / `测试访问`。列表显示子目录与文件（目录可点击进入，空目录显示 `（空目录）`）。

## 九、关键概念与口径说明

### 9.1 「观察期 / 待恢复」（失效宽限期）

当媒体库里的 nfo 目录/文件消失（被删、洗版、临时移走）时，插件**不会立刻删记录**，而是把相关行标记为「待恢复」并进入**观察期**（默认 24 小时，见设置 `失效宽限期（小时）`）：

- 观察期内重新入库 → 按**稳定媒体身份**（Emby ID / TMDB / TVDB / IMDb / nfo 路径）自动恢复，**不重问 AI**（译文还在）。
- 超期仍未恢复 → 判定为真删除，由维护逻辑清理（也可在仪表盘「失效 / 待恢复」里点 `清除` 立即处理）。
- 表现：库页条目红色 `待恢复` chip / 黄色 `N 集待恢复` chip；仪表盘右列「失效 / 待恢复」。
- **只标真正消失的那几集**：若整个剧容器仍在 Emby（只是少了几集），只把那几集标记，同剧其它集不受影响。

### 9.2 人名池三种状态怎么来的

- **待翻译**：没有有效译文，且原文也不是中文。
- **无需操作**：原文本身就是中文（含汉字、无假名，夹空格的「角田 雄二郎」也算）。
- **待同步**：已有目标名，但 Emby 当前名 ≠ 目标名（等写回 Emby）。
- **已同步**：Emby 当前名 == 目标名。
- **同步失败**：写回 Emby 时失败（可重试）。

### 9.3 「翻译完成」≠「写回完成」

- 翻译只写插件的**数据库**；写回才动**nfo 文件**。
- 对应两个徽标：库页 `待翻译`（还没翻）与 `待写回`（翻了但没落盘）。
- 关掉「翻译完自动写回 nfo」或打开「预览模式」时，需要手动点 `全部写回`。

### 9.4 人工修正优先级最高

- 在库页/人名池页点铅笔改的译文，来源记为 `manual`，**重跑扫描/翻译不会被 AI 覆盖**。
- 若要让它重新按 AI 翻，请用「重译已有中文名」或对条目「重新翻译」。

### 9.5 角色翻译记忆

- 第二排角色名会按「剧」记忆跨集复用（同一角色在各集只翻一次）。
- **删除 / 恢复 / 清空翻译记录都不会清这条记忆**，只有编辑弹窗里的 `清除该剧角色记忆` 会。

### 9.6 限流与熔断

- `请求间隔`（唯一的限速项）与 `TPM 令牌预算` 共同控制节奏。
- 遇 429 / 配额 / 网络错误时：自动退避重试；连续失败会进入**限流暂停 / 认证暂停 / 配额暂停**（状态灯可见），修好后自动恢复。
- 失败词条会进「翻译失败词条」清单，可 `重试失败项`。

## 十、典型使用流程

**首次使用（推荐顺序）**

1. 设置页 → 打开 `启用插件` + 配置 LLM（`测试连接` 通过）→ `保存配置`。
2. 设置页 → 「NFO / 扫描」勾选媒体库，必要时配「路径映射」，点 `测试全部路径` 确认可访问。
3. 仪表盘 → `NFO 扫描` 跑一次全量（这一步只采集入库；是否自动翻译看第 4 步开关）。
4. 库 → 点 `全部翻译`（或在设置页打开自动翻译开关）→ 翻完后看 `待写回` 徽标，必要时点 `全部写回`。

**日常自动化（推荐）**

1. 设置页打开 `Webhook 入库后自动翻译`（新剧集入库自动翻）。
2. 打开 `探测库`（定时双向对账，兜底漏事件）。
3. 需要「同一个人名全局复用」时，去人名池页 `拉取人名`（可开 `自动翻译新拉取的人名`）。

**只想要中文人名、不想要角色名**：设置页「翻译范围」关掉 `第二排：角色名`。

**只想先看译名、暂不落盘**：打开 `预览模式（不落盘）`，确认后到库页点 `全部写回`。

**换 LLM / 调提示词**：设置页「LLM 设置」改完 `保存配置` → `测试连接`。

## 十一、使用注意事项（重要）

> 这一节是「怎么用最省心、最不容易出岔子」的经验总结，建议先读完再上手。

### 11.1 尽量只使用一台 Emby 服务器

插件**支持**多服务器（设置页会按服务器分组显示媒体库、人名池也按服务器隔离），但**建议只配置 / 只使用一台**。

原因：删除标记、观察期恢复、人名池同步这些环节都依赖「这条记录属于哪台服务器」。多台服务器时，同名作品、相同路径、以及升级前留下的「空来源」历史行都可能归属不明，插件只能采取更保守的策略（宁可不动，也不误改），于是：

- 有些操作会变成「需人工确认」，自动化程度下降；
- 极端情况下同一部作品的记录会在两台服务器之间重复。

**一台服务器时，插件能做最严格也最省心的自动判定**。确实要多台也行，但请保证每台 Emby 的媒体库路径**不重叠**，并给每台都配好「路径映射」。

### 11.2 任务跑起来后，尽量让它一次跑完 —— 少用「暂停 / 终止」

翻译与写回都是**分批**进行的。虽然暂停 / 终止都会保留进度与断点（之后可以「继续」或「续跑」），但中途打断容易出现「半成品状态」：

- **写回阶段被打断** → 会出现「库里已有译文、nfo 还没写」的情况（看库页 `待写回` 徽标即可发现），需要再点一次 `全部写回` 补齐；
- **翻译阶段被打断** → 当前批次可能只翻了一半，剩下的仍在「待翻译」里（看 `待翻译` 徽标）；
- **扫描阶段被打断** → 断点会保留，下次「续跑」继续，但如果中途改了设置（媒体库、路径映射、类型开关），旧断点可能作废，得重跑全量。

**建议**：

- 要跑就挑空闲时间让它跑完；想「先看看效果」用 **预览模式（不落盘）**，而不是靠暂停来控制；
- 真要停：优先用 **暂停**（可原地继续），**终止**只在「必须马上停」时用；
- 停完记得回来看一眼 `待翻译` / `待写回` 两个徽标，把它们清零再算完事。

### 11.3 有任务在跑时，不要改设置

任务启动时会**冻结一份配置快照**（翻译范围、人数上限、写回策略、分批方式等），运行中改的设置**要到下一个任务才生效**——这是为了避免同一个任务前后行为不一致。

所以在任务运行中改设置，很容易产生「我明明改了怎么没生效」的错觉。**要改设置，等任务跑完再改。**

### 11.4 手动修改「第一排」人名要三思（最容易出错的地方）

第一排人名是**按人名全局**记账的：

| 范围 | 影响面 | 什么时候用 |
|---|---|---|
| `仅这一条` | 只改这一条记录 | **默认选择**，最安全 |
| `该作品内同名` | 该作品所有季/集里的同名人物 | 同一部作品内确认是同一人 |
| `全库同名`（红） | **全库所有作品里的同名人物** | 只在**确认是同一真人**时才用 |

⚠️ **「同名」不等于「同一人」**。日文声优、演员重名很常见（尤其是译名简写、罗马音撞名），「全库同名」可能把 A 作品的演员改成 B 作品演员的译名，而**这个改动不会被 AI 覆盖**（人工修正优先级最高），一旦改错，只能再手工改回来。

**推荐流程**：先「仅这一条」→ 确认无误后需要扩面再选「该作品内同名」→ 只有百分百确认是同一人才用「全库同名」（弹窗还会再确认一次）。

另外两个相关提醒：

- 勾 `同步到 Emby` 会**直接改 Emby 里的 Person 实体名**，该演员在所有作品中的显示名一起变（全局生效）——默认不勾，勾之前想清楚；
- 想「全部推翻让 AI 重来」时，请用设置页的 `重译已有中文名` 或库页的 `重新翻译`，**不要**用「清空」——清空会连人工修正一起删掉。

### 11.5 清空 / 清除类操作，先导出备份

库页 `导出` 与人名池页 `导出` 都能把数据存成 JSON。以下操作**不可恢复**，做之前建议先导出：

- 库页 `清空`（清空翻译记录；人名池保留）
- 人名池页 `清除人名池`（两级确认，连人工修正一起删）
- 仪表盘失效列表的 `清除`（立即判定真删除，不再等观察期）

### 11.6 首次全库扫描不要一上来就开自动翻译

首次全库扫描会一次性产生大量词条（整库的人名 + 角色名）。建议：

1. 先**关掉**自动翻译开关，只跑 `NFO 扫描` 把内容采集入库；
2. 去库页点 `待翻译` 徽标看「待翻译明细」，确认范围（类型开关、人数上限）符合预期；
3. 再点 `全部翻译`，或打开自动翻译开关。

### 11.7 观察期内不要急着「清除」

目录/文件从磁盘消失（洗版中、临时移走、重新下载）时，插件会先进**观察期**（默认 24 小时）。这期间：

- 把文件放回去重新入库 → **自动恢复**，而且是按稳定身份恢复，**不会重问 AI**（译文还在）；
- 只有当它真的不回来了，再去仪表盘失效列表点 `清除`。

所以看到红色 `待恢复` 先别慌，也别急着清。

## 十二、遇到问题怎么办（排查手册）

> 排查第一步永远是：**仪表盘 → 实时日志**（最详细的现场）+ **顶部状态灯**（一眼看出是 LLM 问题还是任务问题）。

### 12.1 「Emby 入库了，插件没反应」

1. 设置页 → `启用插件` 是否打开（关了会明确提示「插件未启用」）；
2. 设置页 → 「Webhook 入库」→ `启用 Webhook 入库` 是否打开；关了仪表盘会有横幅提示；
3. Emby 端是否配置了指向 MoviePilot 的 Webhook，且勾选了「媒体库 → 新媒体添加」类事件；
4. 仪表盘「Webhook 最近事件」：
   - 没有记录 → 事件根本没到 MP（去查 Emby 端的 webhook 配置 / 网络）；
   - 有「待配置」→ 见 12.2；
   - 有「失败」→ 看消息里的原因；
5. 记住了：`入库延迟（秒）` 默认 **60 秒**，刚入库时「没反应」是正常的，等一分钟。

### 12.2 提示「待配置 N」

**原因**：事件里的文件路径不在你所选的媒体库映射范围内，插件不敢乱动，于是挂起等配置。

**处理**：设置页 →「NFO / 扫描」→ 勾选对应媒体库（必要时配 `路径映射`）→ 回仪表盘点 `继续处理`；如果这批事件你根本不想要，点 `放弃全部`。

### 12.3 条目出现红色「待恢复」/「N 集待恢复」

**原因**：磁盘上的 nfo/目录消失了（删除、洗版、临时移动）。

**处理**：

- 只是洗版 / 挪走 → **放回去重新入库即可自动恢复**（观察期内）；
- 确实删除了 → 不用管，观察期（默认 24 小时）到期会自动清理；
- 想立刻清掉 → 仪表盘失效列表 `清除`（不可恢复，先确认真的不回来了）。

### 12.4 翻译完了，但 Emby 里还是英文

按顺序查：

1. 库页看 `待写回` 徽标：**有数字 = 翻译了但没落盘** → 点 `全部写回`；
2. 设置页「翻译完自动写回 nfo」是否被关掉？「预览模式（不落盘）」是否开着（开着就永远不自动落盘）；
3. 落盘后 Emby 仍显示旧名 → Emby 端刷新元数据；建议打开 `翻译后锁定 Cast`，这样 Emby 重刮不会把中文名单覆盖；
4. 只有一部分人没变 → 看这些人是不是被「类型开关 / 人数上限」挡住了（库页 `待翻译` 徽标 → 待翻译明细）。

### 12.5 一堆「翻译失败词条」

1. 先看**失败原因**与 **LLM 灯**：
   - `限速` / `限流暂停` → 加大 `请求间隔（秒）`，必要时填 `TPM 令牌预算`；
   - `配额不足` → 服务商额度用完，充值或换 Key；
   - `认证失败` → Key 不对 / 过期，去设置页 `测试连接` 复核；
   - `上下文过长` / `空响应` → 看 12.6；
2. 处理完外部原因后，点 `重试失败项`；
3. 旧条目失败不影响新条目继续，失败清单可以随时重试或清空。

### 12.6 「测试连接」失败 / LLM 报错

| 现象 | 处理 |
|---|---|
| 连接失败 / 404 | `API 地址` 通常要带 `/v1`（插件会自动尝试补全，但写全最稳） |
| 401 / 认证失败 | `API Key` 填错、失效，或该 Key 无此模型权限 |
| 模型不存在 | `模型名称` 写错（要和服商文档一致，含大小写） |
| https 握手失败 | 内网自签证书 → 打开 `关闭 SSL 校验` |
| 连不上公网 API | 打开 `使用代理` |
| 输出为空 / 被截断 | 打开 `禁用模型深度思考`（默认已开）；服务商若不认内置写法，在 `自定义关闭思考参数（JSON）` 里填官方写法 |
| 一直限速 | 加大 `请求间隔`、设置 `TPM 令牌预算` |

### 12.7 名字明明是中文，却还算「待翻译」

两种可能：

1. 该名字**含假名**（如「田中 あいみ」）→ 属于需要翻译的日文名，正常；
2. 该名字是**繁体中文**（如「名塚 佳織」）→ 插件会按需繁转简，也属正常；
3. 名字是简体中文但被判定为「要翻」→ 去库页看「待翻译明细」，多半是被 `重译已有中文名` 打开后强制重翻了。

反过来，**原文本身是中文**（含汉字、无假名，夹空格的「角田 雄二郎」也算）时，人名池状态会显示 `无需操作`，这是正常的——不翻也不同步。

### 12.8 人名池一直有「待同步」不动

- 点 `批量同步`（或在批量翻译弹窗里勾 `翻译完成后自动同步 Emby`）；
- 同步是写 Emby 的 Person 实体，检查 Emby 连接是否正常；
- 池内状态口径：`待同步` = 已有目标名但 Emby 当前名 ≠ 目标名；`已同步` 才会归零。

### 12.9 「库中条目 / 人名池」数字不对

- 库页 `刷新`，人名池页会每 3 秒自动刷新；
- 库中条目按 `item_id` 去重且排除观察期行，所以有「待恢复」的条目不计入；
- 想核对细节：库页搜索框按标题搜，人名池用原文/译名搜索。

### 12.10 扫描很慢 / 扫不到文件

1. 是否勾选了媒体库（没勾 = 没有扫描根）；
2. `扫描子文件夹` 是否开启；
3. 点 `测试全部路径` 看结果：`路径不存在` / `不是目录` / `无读取权限` 会明确告诉你原因；
4. 插件**只认本地 nfo 文件**——媒体库里没有 nfo（Emby 还没刮削出 nfo）时扫不到，请先让 Emby 完成刮削；
5. 首次全量本来就慢，可以 `终止` 后用 `续跑` 接着跑。

### 12.11 想重来某一条

| 目的 | 操作 |
|---|---|
| 只是名单要重采集（保留译文） | 库页 → 选中条目 → `重新拉取` |
| 想让 AI 重新翻 | 库页 → `重新翻译`（可选只翻第一排/第二排） |
| 手改个别名字 | 点铅笔 → `编辑译文`（注意 11.4 的范围选择） |
| 整部作品角色名要重翻 | 编辑弹窗 → `清除该剧角色记忆`，再重新翻译 |
| 全库推倒重来 | 先 `导出` 备份，再 `清空` → `NFO 扫描` → `全部翻译` |

### 12.12 怎么彻底停掉正在跑的任务 / 怎么接着跑

- 停：仪表盘 `终止`（有确认弹窗），断点与进度保留；
- 接着跑：仪表盘 `续跑`（无断点时会置灰并说明原因）；
- 只是临时让一让：`暂停` → 之后 `继续`（人名池进度条上也有暂停/继续）。

### 12.13 换 LLM / 换机器 / 迁移

- **换 LLM**：设置页「LLM 设置」改完 → `保存配置` → `测试连接`。注意有任务在跑时新配置下一个任务生效（见 11.3）；
- **迁移 / 备份**：库页 `导出` + 人名池页 `导出`，新环境用 `导入` 还原（人名池导入还带来源标记与状态）。

### 12.14 插件停用后页面打不开

插件关闭时，除「设置」外的页面会被遮罩（**插件已停用 / 插件已被关闭，其他页面暂不可用**），点 `前往设置启用` 打开开关并 **保存** 即可。

### 12.15 还是解决不了

按这个顺序收集信息再问：

1. 仪表盘 **实时日志**（报错前后 20 行）；
2. 顶部**状态灯**截图（尤其 LLM 与 AI 翻译 Worker 两盏）；
3. 是哪个条目 / 哪个页面 / 点了哪个按钮；
4. 库页「待翻译」「待写回」两个徽标的数字。

```markdown
## Emby 演职人员中文化 (EmbyPeopleLocalize)

利用大模型（LLM）把 Emby 里的演职人员姓名与角色名翻译成规范简体中文并写回 nfo 文件。

**功能特性：**

* **NFO 本地文件模式**：直接读写 tvshow.nfo / movie.nfo / episode.nfo，省请求、不怕 Emby 重刮覆盖
* **人名池全局复用**：同一人名只翻一次，跨全部作品复用，几乎不重复消耗 AI 额度
* **人工修正最高优先级**：手工改过的译文重跑扫描不会被 AI 覆盖
* **四条自动入口**：Webhook 入库 / NFO 扫描·探测库入库 / 拉取人名 / 人工修改，互不重复
* **失效观察期**：目录/集被删先进观察期（默认 24h），期间重新入库自动恢复，超期才判真删
* **限流与熔断**：请求间隔、TPM 令牌预算、限速/配额/认证分级暂停与自动恢复
* **可选 TMDB 辅助**：拉取时用 TMDB 中文别名补译；用 TMDB credits 补「第二排角色名」的空缺英文
* **按类型与人数精细控制**：演员/客串/导演/编剧/制片分别开关 + 每个文件翻前 N 人
* **完整账本**：翻译记录可查、可导出/导入 JSON、可批量写回、可重扫单条

**安装方式：**

1. 在 MoviePilot 插件市场添加本仓库地址
2. 搜索「Emby 演职人员中文化」并安装（V3）
3. 在插件「设置」页配置 LLM 与要处理的媒体库，点「测试连接」验证
4. 仪表盘点「NFO 扫描」跑一次，或打开 Webhook 自动翻译

**与官方「演职人员刮削」(personmeta) 的关系：**

本插件已**缝合官方「演职人员刮削」**的能力：在设置页打开「人名池 → **拉取时用 TMDB 刮削补译**」后，会按条目的 TMDB ID 取**中文别名**（繁体在拉取环节即繁转简）→ 演员中文名入池并随同步流程统一写回 Emby，同时把**中文简介与头像**即时写回 Emby（简介含锁定）。开启后可停用 personmeta 插件；该能力不依赖 AI（TMDB 查询不经 LLM），AI 总开关关闭时同样可用。

**详细使用说明见 [Emby 演职人员中文化使用手册](https://github.com/LXT-A-X/MoviePilot-Plugins/blob/main/plugins.v3/embypeoplelocalize/README.md)**
```
