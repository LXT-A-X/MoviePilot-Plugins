## 一、它解决什么问题

家里跑着 OpenClash（或 Mihomo 内核）的人，日常其实只有几件事：**看一眼现在走哪条线、某个节点是不是抖了、把默认出口换一个、确认「我到底能不能上某个网站」**。这些事原本要打开路由器后台，再点进 OpenClash 的 LuCI 页面，或者另开一个 zashboard 网页；如果人在外面，就只能等回家。

这个插件把上面这些操作收进 MoviePilot：

1. **一个面板看全**：内核版本、规则模式、运行模式、连接数、内存 / CPU / 负载、上下行速率与累计流量、端口占用、订阅源、全部策略组与节点——打开就是结论，不用再翻 OpenClash 后台。
2. **换节点不用回路由器**：在面板里点节点即可切换；也可以让 Telegram 机器人带按钮，手机上直接点组 → 点节点 → 生效。
3. **测速有依据**：单个节点测延迟、整组批量测速带进度，哪条线掉速一眼看出来，不用凭感觉切。
4. **访问检查给「能不能上」一个数字**：同一个站点可以从「内核出口」「MoviePilot 容器网络」「OpenClash 代理端口」三个视角各测一次，方便区分「是机场不行」还是「MoviePilot 的容器网络不行」。
5. **可选的路由器运维**：填上 LuCI 地址与账号后，可以在这里启停 / 重启 OpenClash、切换运行模式（基础 / TUN / MIX）、切换配置文件、更新订阅、清 DNS 与 Smart 缓存、改区域绕过 / 域名嗅探 / DNS 代理 / 流媒体解锁。
6. **首页仪表盘组件**：MoviePilot 首页加一个全宽小组件，状态、访问检查、策略组与默认组的节点都在一屏内。

一句话：**它不负责「跑代理」（那是 OpenClash 的工作），它负责把 OpenClash 的状态与开关接到你每天都会打开的 MoviePilot 里。**

## 二、核心功能逐项说明

插件页面打开后有 **面板 / 日志 / 设置** 三个标签页；顶栏有「刷新」「完整面板」「退出」三个按钮，右上角会根据内核类型显示 **Mihomo** 标记（内核返回 `meta: true` 时显示）。

### 2.1 状态总览

页面第一张卡片是「总状态」，左边是标题与运行模式标签，右边是「重启」和「刷新」按钮。

卡片内是一组状态格：

| 状态格 | 数据来源 | 说明 |
| --- | --- | --- |
| 内核 | Clash `/version` | 显示内核返回的版本字符串原文 |
| 模式 | Clash `/configs` 的 `mode` | 规则 / 全局 / 直连（界面已翻译成中文） |
| 运行模式 | LuCI `get_run_mode` | 基础 / 增强(TUN) / 混合(MIX)，**需启用 OpenWrt 管理**才取得到 |
| 连接 | OpenClash 资源面板，回退到 Clash `/connections` | OpenClash 的资源面板不可用时用 Clash 实时连接数 |
| 内存 | OpenClash 资源面板 | 路由器上 OpenClash 进程占用的内存 |
| CPU | OpenClash 资源面板 | 瞬时采样，空闲时通常显示 0% |
| 负载 | OpenClash 资源面板 | 系统负载（load average） |
| 上传 / 下载 | OpenClash 资源面板 | 当前实时速率 |
| 累计上传 / 累计下载 | 资源面板，回退到 Clash 累计流量 | 内核启动以来的累计流量 |

> **内存 / CPU / 负载 / 实时速率 / 累计流量**这几项来自路由器 LuCI 的 OpenClash 资源接口，只有勾选「启用 OpenWrt 管理」并填好地址与密码后才有值；未启用时显示 `—`。CPU 那一格是后台瞬时采样，OpenClash 空闲时本来就经常是 0，多刷一次会取两次采样中较大的值。

### 2.2 策略组与节点

面板下方的「策略组」区域是本插件最常用的部分：

- 顶部一行显示 **已识别到的策略组数量**、右侧是「测本组延迟」按钮和批量测速进度（例如 `48/120`）。
- 下面是策略组胶囊（chip），每个胶囊显示组名与「成员数量」。点胶囊切换当前展示的组。
- 当前组的信息行会显示：组类型（如 `Selector` / `URLTest` / `Fallback` / `LoadBalance` / `Relay` / `Smart`）、当前选中的节点、以及「点延迟徽章或『测』可单独测速」的提示。
- 节点以卡片网格展示（手机 1 列、平板 2 列、桌面 4 列），选中的节点会高亮并打勾；带「组」标签的成员表示它本身也是一个策略组（可以嵌套选择）；每个节点右侧有单项测速按钮和延迟徽章。
- **点节点卡片即切换**。切换成功后会自动重新拉取一遍状态（状态、策略组、订阅源），让高亮立刻更新。

关于顺序：策略组**按 OpenClash 配置文件里的顺序排列**，与 zashboard 看到的顺序一致。实现上优先用 Clash `GLOBAL.all` 的顺序；如果内核没给，则回退到语义排序（「默认代理」「全部节点」这类名字优先，其次按地区关键词，最后按名字），`GLOBAL` 组在没有配置顺序可用时排在最后。这样做的好处是：你在 OpenClash 里怎么排，这里就怎么显示，不会出现「面板里组很多、找不到刚才那个」的问题。

关于 Smart 智能组：OpenClash 的 smart 内核会生成 `type=Smart` 的自动选路组，它的「当前出口」是内核自己算的。插件对这类组：

- 照常显示成员、照常可以单项 / 整组测速；
- 会显示「智能自动选路」而不是某个节点名；
- **不允许在组内手动指定节点**：点节点会提示「智能组（Smart）由内核自动选路，不能在组内手动指定节点；可在上层组里选择这个智能组」，后端与 TG 命令同样会拒绝；
- 需要固定出口时，请到上层普通策略组里选择这个智能组。

### 2.3 延迟测速

测速有三种粒度：

1. **单项测速**：点节点卡片上的「速度表」图标或延迟徽章，只测这一项。测的是「节点 / 组」的延迟，不会顺手切换节点，所以可以放心点。
2. **整组测速**：点「测本组延迟」。普通组按每批 8 个成员依次提交（避免一次把内核对爆），顶部显示 `已测/总数` 进度；结束时提示「测速完成：N 项全部成功」或「测速完成：N 成功，M 超时/失败」。Smart 组只测组本身一次（内核会把成员一起测掉）。
3. **订阅源测速**：没有单独的按钮，但订阅源里的每个节点都出现在策略组成员里，整组测速即可覆盖。

测速时用到的参数就是设置页里的「测速地址」和「测速超时」，批量测速的并发由「测速并发数」控制（默认 8；单项测速固定并发 1）。默认测速地址是 `https://www.gstatic.com/generate_204`，超时 5000 毫秒。

延迟颜色的含义（面板）：

| 颜色 | 条件 | 含义 |
| --- | --- | --- |
| 绿色 | `< 200 ms` | 很快 |
| 橙色 | `200 ~ 499 ms` | 一般，可接受 |
| 红色 | `>= 500 ms` | 慢，或测速失败（超时 / 出错） |
| 灰色「—」 | 还没测 | 未测速 |
| 「不可测」 | 类型被跳过 | 该成员是 `Reject` / `RejectDrop` / `Pass` / `Block` / `Compatible` 这类不可测类型 |

还有几个实现细节值得知道：

- 组测速返回的可能是「成员 → 延迟」的映射，插件会把每个成员的延迟拆开写进延迟状态，所以整组测完，组内每个节点的徽章也会一起更新。
- 一次请求最多测 300 个名字（防止误操作把几千个节点一次全丢出去）。
- 单个节点测速失败时，徽章显示「超时」；再点一次可以重测，不必刷新页面。

### 2.4 代理模式与运行模式

这两个概念很容易混，面板上分别用两张卡片、一组按钮呈现：

| 卡片 | 影响什么 | 取值 | 生效方式 | 需要 OpenWrt 管理 |
| --- | --- | --- | --- | --- |
| **代理模式** | Clash 内核的**规则模式**（流量怎么走） | 规则 `rule` / 全局 `global` / 直连 `direct` | 直接调 Clash `PATCH /configs`，立即生效 | 不需要 |
| **运行模式** | OpenClash 的**运行方式**（怎么接管流量） | 基础 / 增强(TUN) / 混合(MIX) | 调 LuCI 切换，**会重启 OpenClash** | 需要 |

代理模式按钮是「规则 / 全局 / 直连」，当前模式的按钮会高亮；切换会立刻把 `mode` 写进内核，并在成功后刷新一次面板。注意：**这是运行时切换，OpenClash 重启后会回到配置文件里写的 mode**，需要长期固定请到 OpenClash 配置里改。

运行模式按钮是「基础 / 增强(TUN) / 混合(MIX)」，点击前会弹确认框：「切换运行模式为「…」？会重启 OpenClash，全屋网络会短暂中断。」确认后调 LuCI 的 `switch_run_mode`。切换成功后页面提示「已切换运行模式为 …（正在重启 OpenClash）」，1.5 秒后自动重新读取 OpenWrt 状态。

### 2.5 订阅源

「订阅源」卡片列出 Clash 里所有真正的**订阅 provider**（内部会过滤掉 Clash 配置里内联的 Compatible 伪 provider，只保留从订阅地址拉取的节点源）：

- 每一行显示：**名称 · 节点数**、更新于（订阅的更新时间，格式化为本地时间；内核给的是无效时间时显示「未知」）、右侧「刷新」按钮。
- 点「刷新」会调 `PUT /providers/proxies/{name}` 触发该订阅重新拉取，提示「已触发 … 订阅更新，节点稍后刷新」。节点不会立刻变，等内核拉完订阅后点刷新或等自动刷新即可。
- 如果没有任何订阅源，卡片显示「暂无订阅源」。

启用 OpenWrt 管理后，卡片底部还会多出一块**订阅流量信息**：从 LuCI 的订阅信息接口读取每个订阅的「流量剩余」与「剩余天数」（有值才显示）。

### 2.6 访问检查（三种视角）

「访问检查」回答的是「现在能不能上这些网站、大概多少毫秒」。卡片右上角可以在三个视角之间切换，切换即触发一次立刻检查：

| 视角 | 测量方式 | 适合判断 |
| --- | --- | --- |
| **内核**（默认） | 让 **OpenClash 内核**通过 Clash 的延迟测试接口去请求站点：`via=proxy` 的站点走「默认代理组当前选中的节点」，`via=direct` 的站点走 `DIRECT` | 和 OpenClash 官方「访问检查」同一套口径，数字通常最低；判断机场线路本身好不好 |
| **MP 网络** | 由 **MoviePilot 容器**发起 HTTP 请求：`via=proxy` 的站点走 MoviePilot 自己配置的代理（系统设置里的 PROXY / PROXY_HOST），没配就直连；`via=direct` 一直直连 | 判断 MoviePilot 这一侧的网络 / 代理配置有没有问题（例如日志抓取、订阅拉取失败时先看这里） |
| **OpenClash 代理** | 由 MoviePilot 容器发起请求，但**显式走 OpenClash 的混合代理端口**（从 Clash `/configs` 读 mixed-port 或 port，拼成 `http://路由器IP:端口`） | 判断「从容器出发经过路由器代理」这条链路是否通 |

界面表现：

- 每个站点一张小卡片，延迟按 300 ms / 1000 ms 分三档着色（绿 / 橙 / 红），失败显示「失败」。
- 后台采集时卡片右上角出现「检查中」标记，页面每 1.5 秒轮询一次进度（最多 12 次）；结果逐站填进来，不是等全部测完才显示。
- 结果区右上角显示本次结果的时间。
- 如果这个视角有额外说明（例如「MP 未配置代理，国外站点将直连」「OpenClash 代理端口不可用，已回退 MP 代理」），会以一行小字显示在卡片底部。

关于后台采集：插件启用且填了 API 地址与密码后，会起一个**访问检查后台线程**，按「访问检查间隔」循环跑一次当前设置的视角，结果缓存起来供页面和仪表盘直接读取；页面点刷新会立刻触发重测（`refresh=1`），不会重复触发。缓存超过「间隔 + 5 秒」就会被视为过期，页面再次请求时会重新触发。

站点列表在设置页可编辑，每行一个，格式是 `名称|URL|direct/proxy`：`direct` 表示永远直连（用来测国内站点），`proxy` 表示走所选通道（用来测国外站点）。不写第三段时按 `direct` 处理；URL 不写协议时自动补 `https://`；以 `#` 开头的行是注释会被忽略。默认四个站点是百度、网易云音乐（直连）与 GitHub、YouTube（走代理）。

### 2.7 OpenWrt 服务管理

这是插件的「运维」部分，**默认关闭**，只有勾选「启用 OpenWrt 管理」并填好地址 / 用户名 / 密码后才可用。它通过 LuCI 登录（拿到 `sysauth` 会话凭据与 `stok`）后调用 OpenClash 的 LuCI 接口，因此要求：

- 路由器上 LuCI 可访问（http 或 https 都能选）；
- 用户名 / 密码能登录 LuCI；
- 固件里的 OpenClash 是标准 LuCI 版（接口路径 `/cgi-bin/luci/admin/services/openclash`）。

能做的事情分三类：

**① 服务启停**

- 启动 / 停止 / 重启 OpenClash（接口支持三种；面板上提供的是带确认框的「重启」按钮）；
- 面板顶部「总状态」卡片右侧的「重启」按钮有二次确认：「确定重启 OpenClash？会短暂断网！」

**② 运行模式与配置**

- 切换运行模式：基础 / 增强(TUN) / 混合(MIX)，会重启 OpenClash；
- 切换配置文件：下拉选择路由器上已有的配置文件（`config_file_list`），点「切换」后重启 OpenClash；
- 更新订阅：对当前配置文件触发订阅更新（`update_config`），不重启。

**③ 缓存与快捷设置**

- 清 DNS / Fake-IP 缓存（`flush_dns_cache`）；
- 清 Smart 缓存（`flush_smart_cache`，Smart 智能组自动选路的缓存）；
- 断开全部代理连接（调 Clash `DELETE /connections`，不是重启）；
- 重载防火墙规则（`reload_firewall`）；
- 区域绕过：关闭 / 绕过大陆 / 绕过海外（写入 `oversea`，会重载配置）；
- 域名嗅探（`meta_sniffer`）、DNS 代理（`respect_rules`）、流媒体解锁（`stream_unlock`）三个开关。

> 这里的操作大多会**重载或重启 OpenClash**，全屋网络会短暂中断。插件在前端做了二次确认，但确认框只是「防手滑」，不是权限控制——能进这个页面的人本来就有管理员权限。

### 2.8 快捷操作与快捷设置

面板把上面这些高频动作单独放了两张卡片：

- **快捷操作**：关闭连接 / 重置防火墙 / 清 DNS 缓存 / 清 Smart 缓存，每个按钮都带确认框（例如「断开全部代理连接？」「清空 DNS/Fake-IP 缓存？」）。
- **快捷设置**：区域绕过下拉 + 域名嗅探 / DNS 代理 / 流媒体解锁三个开关，改动即提交（同样有确认框，例如「切换区域绕过？会重载 OpenClash 配置。」）。

这些按钮和「OpenWrt 管理」是同一套后端接口，所以**没启用 OpenWrt 管理时点了会提示**：「未启用 OpenWrt 管理或未填写密码（请在插件设置里配置）」。

### 2.9 日志（插件日志 / 内核日志）

日志页有两个来源，用顶部按钮切换：

**插件日志**

- 读取 MoviePilot 为本插件写的日志文件：容器内路径 `/config/logs/plugins/openclashpanel.log`（即 MoviePilot 配置的 `LOG_PATH` 下 `plugins/<插件目录名>.log`）。
- 默认取最后 200 行（接口允许 1~500 行），前端按级别筛选（all / info / warning / error / debug）。
- 文件不存在时显示「文件未生成」，并给出一条说明：插件启用后执行初始化、切换节点等操作会写日志；也可以切到「内核日志」。
- 日志行会被解析成「时间 / 级别 / 内容」三列；解析不了的行按 info 原样显示。

**内核日志**

- 通过 Clash 的 `GET /logs?level=<日志采集级别>` 建立**长连接（流式）**，把内核推过来的日志实时收进内存环形缓冲（最多 500 条），页面展示最近部分。
- 只有插件启用且填了 API 地址与密码时采集线程才启动；没连上会每 3 秒重试，连上时插件日志里会写一条「内核日志已连接：<地址>（level=…）」。
- 级别来自设置页「日志采集级别」（debug / info / warning / error），改完保存会自动重启采集线程。
- 页面顶部有「采集中」标记表示线程在跑；没有内容时提示「暂未收到内核日志（可在设置里调日志级别，或产生一点流量）」。

两个来源可以随时切换，切换会立刻重新拉取（内核日志是读缓冲，不会重新连接）。

### 2.10 远程命令（Telegram / 微信）

插件注册了 6 个命令（分类「工具」）。只要 MoviePilot 已接入消息渠道，就可以在对应会话里发送（能否执行仍受 MoviePilot 自身的用户权限控制）：

| 命令 | 作用 | 是否受「允许远程操作命令」限制 |
| --- | --- | --- |
| `/oc_status` | 查看状态与全部策略组 | 否（查询） |
| `/oc_check` | 访问检查（按设置里的视角） | 否（查询） |
| `/oc_node` | 列出策略组；带参数时切换节点 | 是（操作） |
| `/oc_mode` | 列出规则模式；带参数时切换 | 是（操作） |
| `/oc_refresh` | 刷新全部订阅源 | 是（操作） |
| `/oc_help` | 命令帮助 | 否 |

**Telegram（按钮交互）**

- `/oc_node` 无参数：列出策略组，第 1/共 N 页，每组一个按钮，底部有「◀ 上一页 / 下一页 ▶」与「✖ 退出」；点组名展开节点（每页 8 个），点节点即切换，切换后给出结果并带「↩ 返回组列表 / ✖ 退出」。
- `/oc_mode` 无参数：列出当前模式与三个按钮（规则 / 全局 / 直连），点一下即切换。
- 按钮回调走 MoviePilot 的 MessageAction 事件，插件会尽量**编辑原消息**而不是刷屏；编辑失败时退回发新消息。
- 按钮列表有**有效期**：组件列表缓存 300 秒，过期后点按钮会提示「列表已过期，请重新发送 /oc_node」。

**微信等纯文本渠道**

- 渠道不是 Telegram 时不会给按钮，只发文本列表；切换要用带参数的文本命令：
  - `/oc_node 组名 节点名`（组名 / 节点名都支持精确名字）；
  - `/oc_node 组序号 节点序号`（序号来自最近的 `/oc_node` 或 `/oc_status` 列表，列表同样 300 秒有效）；
  - `/oc_mode rule`、`/oc_mode global`、`/oc_mode direct`。
- 注意组名里可能有空格、emoji 或竖线，用名字匹配时请照抄列表里的完整名字；不确定就用序号。

**命令的通用行为**

- 关闭「允许远程操作命令」后，`/oc_node`、`/oc_mode`、`/oc_refresh` 会直接回复「操作命令已在插件设置中关闭（allow_commands=false）」，查询类命令不受影响。
- Smart 组不能通过命令切节点，会回复「「组名」是智能组（Smart），由内核自动选路，不能手动指定节点。」
- 命令执行异常会在插件日志里记录，并回复「命令执行失败：…」/「操作失败：…」。

### 2.11 仪表盘组件

插件向 MoviePilot 仪表盘注册了一个**全宽组件**（key `main`，名称「OpenClash 状态」，12 栏宽，30 秒刷新，带边框），添加方式：MoviePilot 首页 → 编辑仪表盘 → 添加组件 → 选择「OpenClash 状态」。

组件内容：

- 第一行：状态圆点（内核类型判断：Mihomo 为正常色，否则异常色）、`OpenClash`、内核版本、当前规则模式、「默认代理 → 当前节点」、右侧是连接数与上下行累计流量。
- 第二行：访问检查（按设置里的视角显示 内核 / MP / OpenClash 标签），每个站点一个圆点 + 「名称 延迟」，失败显示「失败」。
- 第三行：策略组（总数），**最多显示前 10 个组**，超出显示 `+N`；当前默认组高亮。
- 第四行：默认组的成员，**最多显示前 10 个**，超出显示 `+N`。
- 整张卡片可点击，点击后跳到插件面板（路由 `#/plugin-app/OpenClashPanel/main`）。
- 组件自己每 30 秒刷新一次；访问检查读取的是后台缓存，不会因为组件刷新而反复重测。

「默认组」的选取规则：组件与面板都优先取名字含「默认代理」的组；面板在没有这个组时还会找「全部节点」，再退回第一个组，组件则直接退回第一个组。

### 2.12 完整面板（zashboard）

设置页的「完整面板地址」是给顶栏「完整面板」按钮用的：点击后在**新窗口**打开这个地址（`noopener`）。默认指向 `http://<路由器IP>:9090/ui/zashboard/`，请按你路由器上实际的 dashboard 路径修改。

注意这个地址是**浏览器**去打开的，不是 MoviePilot 容器去访问的：手机在外网时能否打开，取决于你有没有做内网穿透 / 反代。不想显示这个按钮时，把「显示完整面板按钮」关掉即可。

## 三、安装与启用

### 3.1 确认主程序版本

本插件是 **MoviePilot V3 专属**，插件清单里声明 `system_version: >=3.0.0`。V2 版本库（`package.v2.json`）中没有 OpenClashPanel，所以：

- MoviePilot V3：按下面的步骤安装 **1.12.0**；
- MoviePilot V2：**没有对应版本**，请勿尝试混装。

### 3.2 添加插件市场仓库

1. 打开 MoviePilot → 设置 → 插件市场（不同小版本菜单名可能略有差异）；
2. 找到「插件仓库 / 添加仓库」，填入：`https://github.com/LXT-A-X/MoviePilot-Plugins`；
3. 保存后刷新插件市场列表，等待清单加载完成。

### 3.3 搜索并安装

1. 在插件市场搜索「OpenClash」或「控制面板」；
2. 选中「OpenClash 控制面板」，确认版本显示 **1.12.0**；
3. 点安装，等待宿主完成依赖检查与文件落盘（本插件没有额外 Python 依赖，安装很快）；
4. 安装完成后，插件出现在「已安装」列表里；按 MoviePilot 的常规流程到插件设置里确认「启用插件」开关并保存一次配置，让插件完成初始化。

### 3.4 首次配置

1. 在已安装列表里点插件卡片 → 打开**设置**；
2. 填写 **OpenClash API 地址**：`http://<路由器IP>:9090`（external-controller 的根地址，不要带 `/ui/...`）；
3. 填写 **Dashboard 密码**：OpenClash 里 external-controller 的 secret；
4. 需要路由器运维能力时，再勾选「启用 OpenWrt 管理」并填写地址 / 用户名 / 密码（可选）；
5. 点「保存配置」。

保存后插件会立刻重载配置、重启日志采集与访问检查线程，面板数据随之可读。

### 3.5 启用与打开

- 打开插件页：MoviePilot 左侧栏「系统」分区里会出现 **OpenClash** 入口（图标盾牌网络，权限 admin，排序 55）；
- 也可以在「插件」页的插件卡片弹窗里打开（弹窗右上角有关闭按钮，「退出」会关闭弹窗；侧栏整页时「退出」会跳回插件管理页）；
- 打开后如果提示无法连接，先按 [九、FAQ](#九常见问题-faq) 排查 API 地址、密码与 allow-lan。

### 3.6 推荐的首轮检查清单

| 检查项 | 期望结果 |
| --- | --- |
| 面板「总状态」能显示内核版本与模式 | API 地址 + 密码正确 |
| 策略组数量与 zashboard 一致、顺序一致 | 正常读取 `/proxies` 与 `GLOBAL.all` |
| 点一个非 Smart 组的节点能切换并高亮 | `/switch` 正常 |
| 单项测速能出数字 | 测速地址 / 超时合理，节点可用 |
| 访问检查三个视角都有结果 | 网络与代理配置正常 |
| 日志页能读到插件日志或内核日志 | 采集线程工作正常 |
| 仪表盘组件显示数据 | 组件已添加且插件启用 |

## 四、运行前置条件

### 4.1 MoviePilot 侧

- **MoviePilot V3**（`>= 3.0.0`），并已能正常访问插件市场；
- 管理员账号（插件权限等级 2，侧栏入口为 admin 权限）；
- MoviePilot 容器与路由器的网络可达：容器内能访问 `http://<路由器IP>:9090`；
- 不新增任何 Python 依赖：HTTP 客户端复用宿主自带的 `httpx`，清单文件里的 `requirements.txt` 只有一行注释。

### 4.2 OpenClash / Mihomo 侧

- 路由器上已安装并运行 OpenClash（Mihomo 或 Clash 内核均可）；
- 已在 OpenClash 里开启 **external-controller**（默认 9090）并设置 **Dashboard 密码（secret）**；
- 如果 MoviePilot 不在路由器上（绝大多数情况），需要 OpenClash 允许局域网访问（allow-lan），否则容器连不上 9090；
- 记下 API 地址：`http://<路由器IP>:9090`，不是 `/ui/zashboard/` 的地址（填错也能保存，插件会自动纠正为根地址，但请不要依赖纠正）。

### 4.3 OpenWrt / LuCI 侧（可选）

只有要用「OpenWrt 管理」时才需要：

- LuCI 可以从 MoviePilot 容器访问（http 或 https，端口按固件配置）；
- 有一个能登录 LuCI 的账号（默认管理员常见为 `root`）；
- 固件里的 OpenClash 是带 LuCI 页面的标准版，接口路径为 `/cgi-bin/luci/admin/services/openclash`；
- 若关闭了 LuCI 的密码登录（只允许 SSH key 之类），插件无法登录，就用不了这部分功能。

### 4.4 消息渠道（可选）

- 要用 `/oc_*` 命令，需要 MoviePilot 已接入 Telegram 或其他消息渠道，且机器人能收到你的消息；
- Telegram 额外支持按钮选择；微信等纯文本渠道只能用带参数命令。

### 4.5 浏览器侧（可选）

- 「完整面板」按钮是用**浏览器**打开 zashboard，所以要求你的浏览器能访问该地址（同一局域网，或已做外网访问）。

### 4.6 网络代理注意事项

插件访问路由器 / OpenClash 的所有请求都显式关闭了环境变量代理（`trust_env=False`），避免 MoviePilot 容器里的 `HTTP_PROXY` / `HTTPS_PROXY` 把局域网请求带去代理。这是有意为之：**访问检查的「MP 网络 / OpenClash 代理」两个视角才会使用代理**，其余请求一律直连目标。

## 五、配置项详解

设置页有两处入口，内容一致：

1. MoviePilot 插件管理 → 该插件 → **设置**（宿主弹出的配置窗口，里面渲染的仍是同一套 Vue 表单）；
2. 打开插件页 → **设置** 标签页（内嵌同一套表单，保存走宿主配置更新接口）。

> 保存后配置立即生效：日志采集与访问检查线程会按新配置重启，面板数据在下次自动刷新时更新。

### 5.1 总开关与连接

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用插件 | `enabled` | `true` | 关闭后后台日志 / 访问检查采集线程停止，插件面板不再取数；重新保存开启后线程恢复 |
| OpenClash API 地址 | `api_url` | `http://<路由器IP>:9090`（代码预填常见家用网关地址，安装后请改成你自己的路由器） | external-controller 根地址，只填 `http://IP:端口`，**不要带 `/ui/...`**；没写协议会自动补 `http://`，误填路径会自动截断成根地址 |
| Dashboard 密码 | `secret` | 空（必填） | 即 OpenClash 的 Dashboard 密码 / external-controller secret，请求时以 `Authorization: Bearer <secret>` 发送；未填时所有 API 调用会提示「请先在插件设置里填写 OpenClash Dashboard 密码」 |
| 请求超时（秒） | `timeout` | `8` | Clash API 请求超时；OpenWrt 管理登录/接口也复用这个值。界面最小 2 秒，内核侧最小按 1 秒处理 |
| 日志采集级别 | `log_level` | `info` | 传给 Clash `/logs` 的 level 参数：`debug` / `info` / `warning` / `error`；改完自动重连日志流 |

### 5.2 刷新、测速与界面

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 自动刷新间隔（秒） | `auto_refresh` | `10` | 面板自动刷新状态 / 策略组 / 订阅源的间隔；`0` 表示关闭前端自动刷新；实际最小按 3 秒执行；面板底部会显示「数据每 N 秒自动刷新」 |
| 测速地址 | `delay_test_url` | `https://www.gstatic.com/generate_204` | 测延迟用的 URL（Clash 的 delay 接口参数），建议保留 204 探测地址 |
| 测速超时（毫秒） | `delay_test_timeout` | `5000` | 传给 Clash delay 接口的超时，界面最小 1000 毫秒 |
| 测速并发数 | `max_delay_concurrency` | `8` | 批量测速时的并发（界面 1~32）；单项测速固定并发 1 |
| 显示完整面板按钮 | `show_dashboard` | `true` | 顶栏「完整面板」按钮是否显示 |
| 完整面板地址 | `dashboard_url` | `http://<路由器IP>:9090/ui/zashboard/` | 「完整面板」新窗口打开的地址（浏览器侧访问，不是容器侧） |

### 5.3 访问检查

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 访问检查视角 | `netcheck_mode` | `kernel` | `kernel` 内核（与 OpenClash 官方一致）/ `mp` MoviePilot 容器网络 / `clash` 经 OpenClash 混合端口 |
| 访问检查间隔（秒） | `netcheck_interval` | `30` | 后台采集间隔；代码下限 10 秒；填 0 或留空会按默认 30 秒处理（**不是**「只手动检查」） |
| 访问检查超时（秒） | `netcheck_timeout` | `6` | 单个站点请求超时；内核视角实际按最小 3 秒执行 |
| 访问检查站点 | `netcheck_sites` | 百度搜索（直连）、网易云音乐（直连）、GitHub（代理）、YouTube（代理） | 每行一个：`名称\|URL\|direct/proxy`；`#` 开头为注释；不写第三段按 `direct`；URL 不写协议自动补 `https://`；保存时转成结构化的站点列表 |

### 5.4 远程命令

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 允许远程操作命令 | `allow_commands` | `true` | 控制 `/oc_node`、`/oc_mode`、`/oc_refresh` 这三个**会改变状态**的命令；关闭后它们只回复提示。查询类（`/oc_status`、`/oc_check`、`/oc_help`）不受影响 |

### 5.5 OpenWrt 管理

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用 OpenWrt 管理 | `openwrt_enabled` | `false` | 总开关；不启用时启停 / 运行模式 / 配置切换 / 清缓存 / 快捷设置全部不可用（会提示未启用）。也影响「资源占用 / 订阅流量」数据的获取 |
| OpenWrt 地址 | `openwrt_host` | `<路由器IP>`（代码预填常见家用网关地址） | 路由器 IP 或域名，**不含** `http://`（协议由下一项决定；也兼容直接填完整 URL） |

| LuCI 用户名 | `openwrt_username` | `root` | 登录 LuCI 的账号；不同固件可能是 `root` 或自定义管理员账号 |

### 5.7 界面提示文案与代码行为的差异说明

设置页里有几处提示文案与代码实际行为不完全一致，这里如实说明，避免你按提示配置后「感觉没生效」：

| 界面文案 | 实际行为 | 建议 |
| --- | --- | --- |
| 访问检查间隔提示写「默认 60」 | 代码默认值是 **30 秒** | 以 30 为准；需要更慢就自己改大 |
| 访问检查间隔提示写「0 表示只手动检查」 | `0` 会被当成空值回落到 30 秒，后台线程仍按 30 秒采集；只有前端不再定时轮询 | 想减少后台开销请把间隔调大（如 300），不要填 0 |
| 测速并发数提示「默认 8」 | 一致 | —— |
| 「启用插件」提示「关闭后侧栏入口…不再工作」 | 关闭后采集线程停止、接口不再取数；侧栏入口是否显示由宿主按插件状态处理 | 需要彻底停止请关闭并在设置里保存 |

## 六、使用流程与典型场景

### 6.1 场景一：第一次把插件配起来

1. 确认 OpenClash 已开启 external-controller 并设了 Dashboard 密码；
2. MoviePilot 插件市场添加仓库 → 搜索「OpenClash 控制面板」→ 安装 **1.12.0**；
3. 打开设置，只填两项：API 地址（`http://<路由器IP>:9090`）与 Dashboard 密码；
4. 保存 → 打开插件页 → 「面板」应能显示内核版本、模式、策略组；
5. 若状态正常，再去「设置」里按需打开 OpenWrt 管理，补齐路由器运维能力；
6. 最后到 MoviePilot 首页添加仪表盘组件「OpenClash 状态」。

### 6.2 场景二：日常换一个节点

1. 打开插件页（或点首页组件进入）；
2. 在「策略组」里点你要改的组（比如「默认代理」）；
3. 在节点网格里点目标节点；
4. 成功后提示「已切换：<节点名>」，当前节点与高亮自动更新；
5. 想验证效果：点该节点的延迟徽章单独测一次，或去「访问检查」点刷新看国外站点延迟。

> 如果组的类型是 Smart，请换上层组；Smart 组内的节点只能看、不能点。

### 6.3 场景三：整组测速挑最快

1. 选中目标组；
2. 点「测本组延迟」，等待进度条走完（每批 8 个，进度显示 `已测/总数`）；
3. 结束提示会告诉你成功几项、失败几项；
4. 按延迟颜色（绿 < 200 ms、橙 200~499 ms、红 ≥ 500 ms）挑一个，点它切换；
5. 部分成员显示「不可测」属于正常（Reject / Pass / Block 之类本来就没有延迟）。

### 6.4 场景四：判断「到底能不能上外网」

这是访问检查的典型用法，按顺序看三个视角：

1. **内核视角**：数字正常说明机场线路本身通；
2. **MP 网络视角**：如果内核正常但 MP 视角全部失败，问题在 MoviePilot 容器的网络或它的代理配置（MoviePilot 的系统代理设置），不是机场；
3. **OpenClash 代理视角**：如果 MP 正常但这一路失败，检查 mixed-port 是否开启、路由器防火墙是否允许容器访问该端口、端口是否被别的程序占用。

三个视角都失败时，先回面板看「连接数」与「策略组当前节点」是否正常，再查 OpenClash 自身是否在运行。

### 6.5 场景五：手机在 Telegram 里换节点

1. 发 `/oc_node`；
2. 机器人回一页策略组按钮，点「默认代理」；
3. 回一页节点按钮（当前节点带 ✅），点目标节点；
4. 提示「已切换：组 → 节点」，可点「↩ 返回组列表」继续，或「✖ 退出」结束；
5. 隔了几分钟再点旧按钮会提示「列表已过期，请重新发送 /oc_node」，重发即可。

### 6.6 场景六：用面板做一次路由器运维

1. 确认设置里已启用 OpenWrt 管理（地址 / 用户名 / 密码正确）；
2. 面板「总状态」会多出运行模式、内存、CPU、负载、实时速率；
3. 改运行模式：点「增强(TUN)」→ 确认 → 等 1.5 秒自动刷新；
4. 换配置文件：在「配置文件」卡片选择 → 点「切换」→ 确认（会重启）；
5. 订阅更新：点「更新订阅」→ 确认；
6. 网络异常时先试「清 DNS 缓存」「重置防火墙」，别急着重启。

> 所有会重启 OpenClash 的操作都会让全屋网络短暂中断，家里有人正在看剧时请挑时间。

### 6.7 场景七：首页仪表盘盯状态

1. 首页 → 编辑仪表盘 → 添加组件 → 「OpenClash 状态」；
2. 组件全宽显示，30 秒自动刷新；
3. 平时扫一眼：内核版本与模式对不对、默认组挂在哪个节点、访问检查四个站点是不是绿；
4. 想看细节就点卡片，直接进插件面板。

## 七、与其他组件的联动

这个插件是「OpenClash 的遥控器」，不参与媒体整理、不碰下载器，也不依赖 Emby / Jellyfin。它所在的链路如下：

```text
MoviePilot（管理员浏览器 / Telegram / 首页仪表盘）
        │
        ├── Vue 前端（插件页、设置页、仪表盘组件）
        │        │  宿主 API：/api/v1/plugin/OpenClashPanel/*
        │        ▼
        ├── 插件后端（Python，FastAPI 路由 + 后台线程）
        │        ├── Clash / Mihomo REST API  ──►  路由器 OpenClash external-controller
        │        ├── LuCI HTTP（登录 + OpenClash 控制器）──►  路由器 LuCI
        │        └── 本地日志文件 <LOG_PATH>/plugins/openclashpanel.log
        │
        └── 消息渠道（Telegram 按钮 / 微信文本）
```

### 7.1 与 MoviePilot 宿主

| 宿主能力 | 插件用法 |
| --- | --- |
| 插件框架 / SDK | 继承 V3 插件基类，实现 `init_plugin` / `stop_service` / `get_state` / `get_api` / `get_command` / `get_dashboard` 等 |
| 侧栏导航 | 注册 `OpenClash` 入口（`nav_key: main`，分区 system，权限 admin，排序 55） |
| Vue 联邦前端 | 声明渲染模式 `vue` + `dist/assets`，四个入口组件：Page（整页）、AppPage（主页面）、Config（设置表单）、Dashboard（仪表盘组件） |
| 宿主 API 网关 | 前端通过 `/api/v1/plugin/OpenClashPanel/<path>` 调用，后端路由都声明了 `auth: bear` |
| 仪表盘 | 注册 key `main` 的全宽组件，12 栏、30 秒刷新、带边框 |
| 远程命令 | 注册 6 个 `PluginAction` 命令（分类「工具」） |
| 消息按钮 | 监听 `MessageAction`，处理 `[PLUGIN]OpenClashPanel\|oc:...` 回调 |
| 日志系统 | 通过宿主 logger 写日志，日志文件按 MoviePilot 约定落在 `<LOG_PATH>/plugins/<插件目录名>.log` |
| 配置系统 | 读取/保存插件配置（`openclashpanel_` 前缀），配置页保存走宿主更新接口 |

### 7.2 与 OpenClash / Mihomo 内核

插件只使用 external-controller 的公开 REST 接口，不读写 OpenClash 的配置文件本体。实际用到的接口：

| 用途 | 请求 |
| --- | --- |
| 内核版本 / 类型 | `GET /version` |
| 运行配置（端口、mode、allow-lan、tun） | `GET /configs` |
| 切换规则模式 | `PATCH /configs` `{ "mode": "rule\|global\|direct" }` |
| 全部代理与策略组 | `GET /proxies` |
| 订阅 provider 列表 | `GET /providers/proxies` |
| 实时连接 / 累计流量 | `GET /connections` |
| 切换组内节点 | `PUT /proxies/{组名}` `{ "name": "节点名" }` |
| 刷新订阅 | `PUT /providers/proxies/{订阅名}` |
| 断开全部连接 | `DELETE /connections` |
| 节点测速 | `GET /proxies/{名字}/delay?url=&timeout=` |
| 订阅节点测速 | `GET /providers/proxies/{provider}/{名字}/healthcheck` |
| 策略组测速 | `GET /group/{组名}/delay` |
| 内核日志流 | `GET /logs?level=<级别>`（长连接流式读取） |

所有组名 / 节点名都会做 URL 编码（组名里常带 emoji、空格、竖线），避免请求 404。

### 7.3 与 OpenWrt / LuCI

启用 OpenWrt 管理后，插件用 HTTP 表单登录 LuCI（`POST /cgi-bin/luci`），从响应头或页面里取 `stok`，之后带 `;stok=` 调 OpenClash 的 LuCI 控制器（`/cgi-bin/luci/admin/services/openclash/...`）。会话过期（401/403）会自动重登一次。用到的控制器接口包括：`status`、`get_run_mode`、`config_name`、`oc_settings`、`config_file_list`、`action`、`switch_run_mode`、`switch_config`、`update_config`、`reload_firewall`、`flush_dns_cache`、`flush_smart_cache`、`switch_oc_setting`、`toolbar_show`、`sub_info_get`。

> 注意：如果你的固件改了 OpenClash LuCI 的接口路径或字段名，这部分可能不工作；面板的只读状态（Clash API 部分）不受影响。

### 7.4 与 zashboard / 其他面板

插件不替代 zashboard，也不内嵌它。「完整面板」只是用新窗口打开你配置的地址，复杂编辑（改配置、看日志详情、规则调试）仍然建议去 zashboard 或 OpenClash 自带的 LuCI 页面。两个界面**同时打开不会冲突**，但注意它们改的是同一个内核：你在 zashboard 里切了节点，本插件下一次自动刷新（默认 10 秒）就会看到。

### 7.5 与 MoviePilot 的系统代理

访问检查的「MP 网络」视角会读取 MoviePilot 的系统代理设置（`PROXY` 字典里的 https/http，或 `PROXY_HOST`）。所以如果 MoviePilot 自己配了代理，MP 视角测出来的就是「MoviePilot 走它自己的代理」的结果；没配代理时，国外站点会直连，卡片底部会提示「MP 未配置代理，国外站点将直连」。

### 7.6 与消息渠道

插件不自己发通知，只在收到命令 / 按钮回调时回复。命令注册在 MoviePilot 的插件动作事件上，所以：

- Telegram 支持编辑原消息 + 内联按钮（分页、返回、退出）；
- 其他渠道（如微信）自动降级为纯文本，无按钮；
- 回复发送失败只会在插件日志里记一条 warning，不会影响 OpenClash 本身。

### 7.7 明确不涉及的东西

- 不改 Emby / Jellyfin 的元数据、不触发媒体库刷新；
- 不连接 qBittorrent / Transmission 等下载器；
- 不参与 MoviePilot 的订阅、站点、整理流程；
- 不修改、不备份 OpenClash 的配置文件（切配置只是让 OpenClash 换一个已有配置文件）。

## 八、安全与权限

### 8.1 谁能用

- 插件权限等级为 **2（管理员）**，侧栏入口以 `admin` 权限注册；非管理员账号看不到入口，也调不到插件页面。
- 后端所有 HTTP 接口都声明 `auth: "bear"`，即需要 MoviePilot 的 API Token 鉴权，由宿主统一校验；没有 Token 的外部请求无法直接调用。

### 8.2 凭据保存在哪里

| 凭据 | 保存位置 | 说明 |
| --- | --- | --- |
| OpenClash Dashboard 密码（secret） | MoviePilot 插件配置（键 `secret`） | 以 `Authorization: Bearer <secret>` 发给路由器；插件日志里不打印该值 |
| LuCI 用户名 / 密码 | MoviePilot 插件配置（键 `openwrt_username` / `openwrt_password`） | 只用于登录路由器，不写日志；仅在启用 OpenWrt 管理时使用 |
| MoviePilot API Token | MoviePilot 自身 | 前端调用插件接口时由宿主携带 |

需要说明的现实边界：

- 这两个密码以**普通配置项**形式保存在 MoviePilot 的配置里（本版本没有做额外加密），能访问 MoviePilot 配置 / 数据库的人就能看到。因此：**不要把插件配置截图、导出文件或备份随手发到群里**；共享 MoviePilot 实例时请限制管理员权限。
- 「访问检查」的代理地址在界面展示前会做掩码（`http://***@host`），避免把代理里的账号密码显示出来。
- 插件会在日志里记录操作（切换节点、切换模式、刷新订阅、OpenWrt 操作等），但不会记录密码明文。

### 8.3 只读与可写边界

| 类别 | 行为 | 风险 |
| --- | --- | --- |
| 只读 | 状态、策略组、订阅源、连接数、端口、日志、访问检查、资源占用 | 无副作用 |
| 写运行时状态 | 切换组内节点、切换规则模式、刷新订阅、断开连接 | 会立刻改变全屋出口 / 连接，但不改配置文件 |
| 写路由器服务 | 启动 / 停止 / 重启 OpenClash、切换运行模式、切换配置文件、更新订阅、重载防火墙、清缓存、改快捷设置 | **会重启或重载 OpenClash，全屋网络短暂中断** |
| 不写 | OpenClash 配置文件内容、订阅内容、节点定义 | —— |

重要：**切换规则模式与切换节点都是运行时操作**，OpenClash 重启后会回到配置文件里的设置。需要长期生效请去 OpenClash 里改配置。

### 8.4 危险操作与二次确认

以下操作在前端都有 `window.confirm` 二次确认（只是防误点，不构成权限控制）：

- 重启 OpenClash（「确定重启 OpenClash？会短暂断网！」）
- 切换运行模式（「…会重启 OpenClash，全屋网络会短暂中断。」）
- 切换配置文件（「切换配置文件会重启 OpenClash！」）
- 更新订阅（「更新当前订阅？」）
- 区域绕过（「切换区域绕过？会重载 OpenClash 配置。」）
- 三个快捷设置开关（「切换「X」？」）
- 关闭连接（「断开全部代理连接？」）
- 重置防火墙（「重置防火墙规则？」）
- 清 DNS / Smart 缓存

在面板上切换节点、切换代理模式、单项测速、整组测速、刷新订阅**没有**二次确认（属于高频操作，且后果可逆）。

### 8.5 网络暴露面与加固建议

1. **不要**把 OpenClash 的 9090 端口或 LuCI 直接暴露到公网。如果必须外网访问，走反向代理 + 认证或 VPN。
2. 给 external-controller 设置足够强的 secret；secret 为空时插件会直接报错拒绝调用（它不会以「无密码」方式连接）。
3. 只有在需要路由器运维时才打开「启用 OpenWrt 管理」；用完可以关掉，减少一个可写入口。
4. 如果只是想在 MoviePilot 里看状态 + 切节点，把「允许远程操作命令」保持默认开启或按需关闭：关闭后 TG 只能查询，不能改。
5. 建议给 LuCI 使用独立账号并限制权限（如果固件支持），避免把 root 密码用在自动化脚本里。
6. 使用 https 访问 LuCI 时，请确保 MoviePilot 容器信任该证书，否则会报请求失败。
7. 定期检查 MoviePilot 的日志与插件日志里是否有异常的操作记录。

### 8.6 插件会访问哪些地址

- 配置的 OpenClash API 地址（默认 9090）；
- 配置的 OpenWrt / LuCI 地址（启用后）；
- 测速地址（默认 `https://www.gstatic.com/generate_204`，由路由器内核去请求）；
- 访问检查里的站点（默认百度、网易云音乐、GitHub、YouTube，由内核或 MoviePilot 容器去请求，取决于视角）。

除以上地址外没有其他外部请求；插件不收集、不上报任何数据。

## 九、常见问题 FAQ

### Q1. 面板提示「暂无策略组数据（请检查 API 地址 / Dashboard 密码）」，状态也是空的

**可能原因**：API 地址填错（填成了 zashboard 的 `/ui/...` 地址）、端口不是 9090、secret 为空或错误、MoviePilot 容器到路由器不通、OpenClash 没开 external-controller。

**排查步骤**：

1. 设置页把 API 地址改成 `http://<路由器IP>:9090`（只到端口，不带路径）；
2. 确认 OpenClash 的 external-controller 已开启、端口是 9090、Dashboard 密码已设置；
3. 确认 MoviePilot 容器能访问路由器 9090（不是浏览器能访问就行，**容器**也要能访问）；
4. 若 OpenClash 只监听本机回环地址（对局域网不可见）或限制了来源 IP，请打开 allow-lan 或放行容器所在网段；
5. 看插件日志里的具体报错：`无法连接 OpenClash API：<地址>` 是网络问题，`Dashboard 密码错误（401）` 是 secret 问题。

### Q2. 提示「Dashboard 密码错误（401），请检查插件设置里的密码」

**原因**：插件把 `secret` 当作 `Authorization: Bearer` 发出去，401 表示路由器拒绝了。

**处理**：打开 OpenClash → 插件设置 → 找到 Dashboard 密码（external-controller 的 secret），注意大小写与前后空格；粘贴到插件设置后保存。修改 OpenClash 密码后记得同步改插件配置。若确认密码正确仍 401，检查是否有反向代理改写了 Authorization 头。

### Q3. 访问检查一直「失败」，或者三个视角结果差别很大

先分清视角：

- **内核视角**全部失败：问题多半在机场 / 默认代理组当前节点。回面板看「默认代理」当前挂在哪个节点，换个节点再测；也可能是测速地址被节点屏蔽。
- **MP 网络视角**全部失败：问题在 MoviePilot 容器的网络。检查容器能否正常出网、MoviePilot 系统代理是否配错；注意国外站点在没有代理时会直连（卡片会提示「MP 未配置代理，国外站点将直连」）。
- **OpenClash 代理视角**失败：检查 Clash 的 mixed-port / port 是否开启、容器能否访问「路由器IP:该端口」、路由器防火墙是否拦截；插件会先尝试 mixed/port，不可用时自动回退 MP 代理并在卡片里提示。
- 三个视角都失败（从内核到容器都不通，或站点本身不可达）：把访问检查超时从 6 秒调大（比如 10 秒）再试；网络抖动时短超时会直接判失败。

### Q4. 测速很多节点显示「超时」或「不可测」

- 「不可测」是正常的：`Reject`、`RejectDrop`、`Pass`、`Block`、`Compatible` 这些类型没有真实延迟，插件会跳过；
- 「超时」多为节点本身不可用、测速地址被墙，或超时设得太短。把「测速超时（毫秒）」从 5000 调大（比如 8000）再试；
- 批量测速失败较多时，把「测速并发数」从 8 降到 4，减少路由器瞬时压力；
- 单个节点连点两次测速按钮可以重测（不用刷新页面）。

### Q5. 日志页「文件未生成」，或者内核日志一直没有内容

- **插件日志**：文件在容器内 `/config/logs/plugins/openclashpanel.log`，由 MoviePilot 的日志系统写入。刚安装、还没产生操作时可能不存在；执行一次切换节点 / 保存配置等操作后再看。若长期不存在，检查 MoviePilot 的日志目录挂载与权限。
- **内核日志**：需要插件启用且 API 地址 + 密码正确，采集线程才会启动；页面顶部显示「采集中」说明线程在跑。仍无内容时，把「日志采集级别」调成 `debug` 保存，并在路由器上产生一些流量；连不上时插件日志会每 3 秒记一条「内核日志连接失败，3 秒后重试」。
- 日志读取上限是最近 500 条，日志级别筛选只影响展示，不影响采集。

### Q6. 点了节点没反应 / 提示智能组不能切换

- Smart 智能组（`type=Smart`）由内核自动选路，**设计上禁止手动指定成员**；界面、接口、TG 命令都会拒绝。请在上层普通策略组里选择这个智能组。
- 如果目标节点是另一个策略组（带「组」标签），切换它等于把出口交给该组，本身是允许的；
- 若点了没任何反应，先看是否有 toast 报错（比如 401 / 404），再看插件日志里「切换节点失败：…」。

### Q7. 提示「未启用 OpenWrt 管理或未填写密码（请在插件设置里配置）」

即使你填了地址，以下任一条件不满足都会得到这句提示：

1. 「启用 OpenWrt 管理」开关是关的；
2. 地址为空；
3. 密码为空。

另外，LuCI 登录失败时会提示「OpenWrt 登录失败（用户名或密码错误）」；HTTPS 证书不被信任、端口不对、防火墙拦截则表现为请求失败。逐项检查后再保存（保存后线程与客户端都会按新配置重建）。

### Q8. 重启 / 切换运行模式后，家里网络断了，面板也刷不出来

这是**预期行为**：这些操作会重启 OpenClash，路由器代理进程重启期间全屋网络短暂中断，面板在几秒内取不到数据。等 10~30 秒（或点刷新）即可恢复。若长时间不恢复，去 LuCI 看 OpenClash 是否启动失败（常见于运行模式与固件不匹配，例如固件不支持 TUN 却切到增强 TUN）。

### Q9. Telegram 命令没反应，或者按钮点了提示「列表已过期」

- 命令没反应：确认 MoviePilot 已接入消息渠道、机器人能收到该会话的消息；再看插件日志是否有「处理 OpenClash 命令失败」；
- 提示「列表已过期，请重新发送 /oc_node」：组 / 节点列表缓存 300 秒，超时后要重新发命令；
- 回复「操作命令已在插件设置中关闭」：设置里「允许远程操作命令」被关掉了，查询类命令仍然可用；
- 微信等渠道没有按钮是正常的，请用 `/oc_node 组名 节点名` 或序号形式。

### Q10. 仪表盘组件显示「暂无结果」或一直不刷新

- 组件读取的是插件后台缓存与接口，先确认插件已启用、API 地址与密码正确；
- 组件每 30 秒刷新一次，刚添加时等半分钟；
- 访问检查那一行没结果时，先在插件页点一次「访问检查」刷新，让后台完成一轮采集；
- 内核类型圆点颜色只表示 `/version` 返回的 `meta` 字段（Mihomo 为正常色），不代表网络好坏。

### Q11. 改了 API 地址 / 密码，面板还是旧数据

- 保存配置后插件会立刻重载配置并重启采集线程，但面板数据要等下一次自动刷新（默认 10 秒）；
- 如果你是在插件页「设置」标签里保存的，保存后会主动重新拉取配置与状态；
- 极端情况下宿主配置保存失败时，插件日志会记「写回宿主配置失败：…」，此时需要重新保存；
- 注意 API 地址会被自动纠正：填写 `http://路由器IP:9090/ui/zashboard/` 会保存成 `http://路由器IP:9090`。

### Q12. 访问检查间隔设成 0 了，为什么后台还在跑？

因为 `0` 在代码里会被当成空值回落到默认 30 秒（详见 [5.7](#57-界面提示文案与代码行为的差异说明)）。想降低后台开销，请把间隔调大（例如 300 秒），而不是填 0。

## 十一、附录：HTTP 接口一览

以下接口由插件注册在 MoviePilot 的插件 API 网关下，统一前缀为 `/api/v1/plugin/OpenClashPanel`，全部要求 Bearer 鉴权（`auth: bear`），返回结构统一为 `{success, message, data}` 或 `{success: false, message, code}`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/config` | 读取当前插件配置（含默认值合并结果） |
| POST | `/config` | 保存插件配置（合并提交字段、纠正 API 地址、重启采集线程） |
| GET | `/status` | OpenClash 运行状态（版本、类型、模式、端口、连接、流量） |
| GET | `/groups` | 全部策略组与成员（已按配置顺序排序） |
| GET | `/providers` | 订阅源列表（已过滤内联 Compatible 伪 provider） |
| POST | `/switch` | 切换策略组节点（body：`group`、`name`；Smart 组会被拒绝） |
| POST | `/mode` | 切换规则模式（body：`mode` = rule/global/direct） |
| POST | `/delay` | 单项 / 批量测速（body：`names` 数组，可选 `url`、`timeout`） |
| POST | `/providers/refresh` | 刷新订阅（body：`name`） |
| GET | `/logs` | 日志（query：`lines` 1~500、`level` 逗号分隔、`source` = plugin/kernel） |
| GET | `/netcheck` | 访问检查（query：`mode` = kernel/mp/clash、`refresh` = 0/1） |
| GET | `/ocweb/status` | OpenWrt 状态（运行模式、当前配置、配置文件列表、快捷设置、规则模式、混合端口） |
| POST | `/ocweb/manage` | OpenWrt 管理操作（body：`op` + 对应参数） |
| GET | `/ocweb/info` | 资源占用（`toolbar_show`）与订阅流量（`sub_info_get`） |

`/ocweb/manage` 支持的 `op`：

| op | 参数 | 说明 |
| --- | --- | --- |
| `action` | `action`: start / stop / restart | 启停 / 重启 OpenClash |
| `run_mode` | `run_mode`: `""` / `-tun` / `-mix` | 切换运行模式（重启） |
| `switch_config` | `config_name` | 切换配置文件（重启） |
| `update_config` | `filename` | 更新当前配置文件对应的订阅 |
| `close_connections` | 无 | 断开全部代理连接（走 Clash API） |
| `reload_firewall` | 无 | 重载防火墙规则 |
| `flush` | `target`: dns / smart | 清 DNS 缓存 / 清 Smart 缓存 |
| `setting` | `setting`: meta_sniffer / respect_rules / oversea / stream_unlock；`value` | 修改快捷设置 |

错误约定：参数缺失或非法返回 400（例如「缺少 group 或 name 参数」「mode 必须是 rule / global / direct 之一」「run_mode 必须是空字符串 / -tun / -mix」「target 必须是 dns 或 smart」「不支持的 setting（meta_sniffer/respect_rules/oversea/stream_unlock）」）；上游失败返回上游状态码或 502；未启用 OpenWrt 管理返回 400。
