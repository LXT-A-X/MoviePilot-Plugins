## 一、它解决什么问题

ASS/SSA 特效字幕由字幕组制作，样式里写死了具体字体名（例如「方正筑紫明朝宋 简繁」「DFPOP1-W5」「思源黑体 CN」）。播放器渲染时按名字去系统里找字体，找不到就用默认字体替换，于是出现下面这些问题：

- 字幕变成方块、问号或乱码，完全没法看；
- 字体不对导致排版错位、描边/阴影错位、字幕超出画面；
- 电视、投影、手机、平板分散在客厅各房间，很难给每一台设备都装字体；
- 换一台设备就要重装一遍，字体来源、授权和版本还不好统一管理。

业界已有的成熟做法是「字体子集化内嵌」：只把字幕实际用到的字形从字体文件里裁出来，编码后写进 ASS 的 `[Fonts]` 段。播放器读字幕文件时就能拿到自带字体，不需要系统安装。桌面工具 fontInAss 做的就是这件事，但它需要你手动找字体、手动跑子集化、生成新的字幕文件，再放回媒体库。

本插件把这套流程搬到 MoviePilot 服务端，以「Emby/Jellyfin 反向代理」的形式**实时**完成：

1. 播放器请求字幕；
2. 插件内置反代拦下字幕请求；
3. 回源 Emby 取完整字幕；
4. 解析字幕用到的字体和字符；
5. 从你的字体库匹配字体；
6. 子集化并注入 `[Fonts]`；
7. 把处理后的字幕返回给播放器。

结果是：媒体库里的字幕文件**不会被修改**，播放器**不需要安装任何字体**，同一套字体库供家里所有设备共享；往字体目录里放新字体后，索引会自动更新。

**适用范围与边界（很重要）：**

- 只处理 ASS/SSA 字幕；SRT 可以按开关转成 ASS 后处理；VTT、SUB 等其它格式原样透传。
- 只对「经过插件内置反代端口」的请求生效；直连 Emby 原端口的播放完全不受影响。
- 插件只**读取**字体文件，不修改、不删除、不移动字体库；也不写入媒体库。
- 前提是 MoviePilot 容器能访问 Emby，并且播放器实际连的是插件反代端口。

## 二、核心功能与工作原理

### 2.1 请求分流：一个端口接管所有请求

内置反代在独立端口（默认 8097）监听，把收到的请求分成四类：

| 请求类型 | 典型路径 | 处理方式 |
| --- | --- | --- |
| 字幕流 | `/Videos/{条目}/{媒体源}/Subtitles/{序号}/{位置}/Stream.ass`（也匹配 `.ssa`、`.srt`、`.subrip`，允许带 `/emby` 之类的前缀） | 进入字幕处理链路 |
| 视频/音频大流量 | `/Videos/.../stream.*`、`/Audios/.../universal`、`/Items/{id}/Download`、`/hls1/`、`/hlsmain/`，以及 `.mkv`、`.mp4`、`.ts`、`.mp3` 等常见媒体后缀 | 流式透传：边收边发，支持 Range 断点续播，读超时不设上限（暂停播放不会 30 秒断流） |
| WebSocket | `/embywebsocket`、`/socket` | 双向透传，保住 Emby/Jellyfin Web 端的会话同步与远程遥控（依赖 websockets 库） |
| 其他 | Web 页面、登录、API、图片 | 缓冲透传，原样转发请求方法与请求体；3xx 重定向的 Location 会被改写成相对路径，避免浏览器跳出反代直连 Emby |

补充说明：

- 字幕识别由路径正则完成，只有 `.../Subtitles/{序号}/.../Stream.ass|ssa|srt|subrip` 这种形态才会处理；没有扩展名或格式不认识的一律透传。
- 反代为纯 Python 实现，复用 MoviePilot 自带的 uvicorn/starlette，不需要额外二进制，也不需要安装 nginx。
- 从 3.1.0 起，插件只保留内置反代这一个入口，不再在 MoviePilot 主端口注册匿名字幕端点；网上一些早期教程里的 nginx 写法已不再需要（如需 HTTPS 或统一域名，仍可以在 8097 前自行加一层反代）。

### 2.2 字幕处理链路（12 步）

每次处理都会按顺序写日志，排障时可以照着日志逐步对照：

1. **识别字幕请求**：匹配字幕路径，取出条目 ID、媒体源 ID、字幕序号、StartPositionTicks、格式。
2. **回源取完整字幕**：把地址里的 StartPositionTicks 归零，请求整条字幕（字形覆盖必须按完整字幕计算），并剥离客户端的 Range/If-Range，避免只拿到 206 片段。日志：`字幕URL: ...`。
3. **识别编码**：按 BOM（UTF-32 / UTF-8 / UTF-16）→ UTF-8 → GB18030（先做可打印率校验）→ charset-normalizer 探测。全部失败则记录「字幕编码无法识别（透传原始）」。
4. **已是子集字幕则跳过**：字幕里同时存在 `[Fonts]` 段和 `fontname:` 行时，说明已经内嵌过字体，直接原样透传，不二次注入。
5. **SRT 转 ASS（可选）**：开启「SRT 转 ASS」时，把 SRT 文本转成带 `[V4+ Styles]` 的 ASS，字体、字号、主色取设置页的 SRT 配置；关闭时 SRT 原样透传。
6. **索引就绪检查**：字体索引还没扫描完，本请求透传；重建索引期间同样透传，绝不阻塞播放。
7. **解析 ASS 字符集**：按 `Format:` 行动态定位列（不硬编码列号）；解析样式表、`Dialogue` 行，处理 `\fn` 切字体、`\r` 切样式、`\b`/`\i` 切字重/斜体；剥离 `{...}` 特效块；`\N`、`\h` 等占位符不进入字符集。
8. **字体匹配**：按字体名 + 字重 + 斜体匹配（详见 2.4）。
9. **子集化**：uharfbuzz 优先，失败回退 fontTools；只保留实际用到的字形，并保留 `name` 表（播放器要靠它按字体名匹配内嵌字体）。
10. **UUEncode 编码**：按 fontInAss 的变体规则编码成 ASCII（80 字符行宽、偏移 33、无长度字节与结束标记）。
11. **注入 `[Fonts]`**：拼成 `fontname:字体名_B I0.ttf` 形式，插入到 `[Events]` 之前。
12. **按时间窗裁剪**：请求带 StartPositionTicks（拖动进度后再拉字幕）时，丢弃 `End <= 起始位置` 的旧对白，只返回当前时间窗之后的内容；时间轴本身不做偏移。

处理完成后的响应头固定为：`content-type: text/x-ssa; charset=utf-8`、`X-FontInAss: 1`、`Cache-Control: no-cache`，正文是带 BOM 的 UTF-8 ASS。在浏览器开发者工具里看到 `X-FontInAss: 1`，就说明这个请求确实走了插件处理链路。

### 2.3 字体索引：SQLite + 目录监听

- 递归扫描「字体目录」下的 `.ttf`、`.otf`、`.ttc`、`.otc`；`.ttc` 字体集合会按 face 逐个解析。
- 每个 face 记录 family、subfamily、fullname、psname、字重、斜体、mtime、大小，并把这些名字拆成别名存入 SQLite；索引库放在插件数据目录（`fontindex.db`）。
- 名称解码做了多路择优：同一条名字记录会依次尝试 UTF-16BE、UTF-16LE、GBK、GB18030、BIG5，按「汉字加分、假名加分、韩文减分、控制字符减分」打分取最优，解决中文字体名在 GBK/BIG5/UTF-16 下乱码导致的匹配失败。
- 只采集 Windows 平台的名字（字幕里写的通常就是 Windows 下看到的字体名）；只带 Mac 名字的字体回退全平台，避免索引里没有可用别名。
- 启动时后台线程全量扫描，不阻塞 MoviePilot 启动；扫描完成后日志写「字体索引就绪: N 个 face」。
- watchdog 监听目录变化，新增/修改/删除字体单文件增量入库；如果环境里 watchdog 不可用，自动降级为 60 秒轮询。
- 索引结构有版本号（当前 schema 3）。插件升级导致结构变化时会自动删表重建，不需要手动处理。
- 索引版本号会参与字幕缓存 key：字体库有任何变化，旧缓存自动失效，不会拿到「按旧字体库生成的」字幕。
- 状态页「重建字体索引」按钮可强制全量重建；重建期间索引标记为未就绪，字幕请求一律透传，重建完成后自动恢复。

状态页「字体索引」卡片会显示 face 数、是否就绪、扫描进度、fontTools 版本，以及 uharfbuzz 是否可用。

### 2.4 字体匹配：先严格全等，再模糊打分

匹配分两层，避免「模糊匹配越级压过精确匹配」：

**第 1 层：严格全等。** 把查询名和候选名都做归一化（去掉空格、下划线、连字符，转小写），只要与内部名（family / subfamily / fullname / psname）、任意别名或文件名字干完全相等，就算命中。命中后按下面的顺序挑一个：

1. 容器格式优先级：ttf（3）> ttc（2）> otf（1）> otc（0）。ASS 规范只保证 TrueType，所以 ttf 最稳；
2. 属性距离：字重差 + 斜体不一致（不一致记 110）；
3. 路径字典序（保证结果稳定）。

**第 2 层：模糊打分。** 第 1 层完全没有候选时才启用，分数最高且不低于阈值 0.6 才算命中：

| 情况 | 基础分 |
| --- | --- |
| 内部名（含别名）精确相等 | 0.95 |
| 文件名字干精确相等 | 0.90 |
| 内部名包含 / 互为前缀 | 0.75 |
| 文件名包含 | 0.72 |
| 分词集合重叠（英文、日文名有效） | 0.4 + 0.5 × 重叠率 |
| 中文 2 字滑窗 gram 覆盖（宽松兜底） | 0.45 + 0.4 × 覆盖度 |

然后叠加容器格式加成（ttf +0.03、ttc +0.02、otf +0.01、otc 0；幅度小于相邻档位差，只在名字打平时起作用）与属性惩罚（字重差 >150 减 0.15、>50 减 0.06；斜体不一致减 0.10）。

这样设计的原因：日系/华康字体常把字重信息放在名字里（例如 `DFPOP1-W5`），而字体内部的 usWeightClass 可能是 400，ASS 字幕却常标 Bold(700)。3.1.1 起把字重/斜体惩罚降档，避免「名字明明对上了，却因为字重差被扣到阈值以下、静默兜底成默认字体」。

如果某一层都没命中，插件会：

- 用「SRT 兜底字体」（默认「思源黑体 CN」，按 400 字重、非斜体匹配）替换显示，并记录一条缺失，日志：`字体未匹配 {字体名}，已用默认字体兜底替换`；
- 如果连兜底字体也没匹配到，则本请求失败，按「处理失败」策略返回（默认透传原始字幕）。

匹配结果有进程内 LRU 缓存（最多 1024 条，索引版本变化立即清空），所以同一部剧反复播放不会反复查库。

### 2.5 子集化引擎与性能

- 优先用 **uharfbuzz**（HarfBuzz 的 C 实现）做子集化；未安装或单次失败时自动回退 **fontTools**，并记警告日志「uharfbuzz 子集化失败，回退 fontTools」。
- 代码注释里的实测数据（15.8MB 思源黑体、800 字）：uharfbuzz 约 9.6ms，fontTools 约 1320ms，相差约 137 倍。字体越大、字幕特效越多，差距越明显。
- uharfbuzz 默认做完整布局闭包（GSUB/GPOS/组合字形），复杂文字（阿拉伯文、缅甸文、天城文等）不会漏字形；fontTools 回退路径也强制保留 `name` 表，否则播放器按名字匹配不到内嵌字体。
- 缺字形检查：uharfbuzz 路径直接用子集化产物的 unicodes 做差集（几乎零成本）；fontTools 路径才重新打开字体读 cmap。
- 字体文件字节有 LRU 缓存，上限 256MB，key 里带 mtime，字体文件被替换后不会用到旧字节。
- 并发控制：用 `threading.BoundedSemaphore(子集化并发上限)` 做全局闸门，线程池大小是并发上限的 2 倍；默认并发 4，即最多 8 个解析线程。请求获取许可最多等 3 秒，等不到就降级透传（日志：`子集化并发已满，请求降级透传`）——宁可字幕晚 3 秒出来，也不让排队把 MoviePilot 主进程拖死。

### 2.6 `[Fonts]` 注入与编码细节

为了让「字体真的能被播放器用上」，编码细节必须和 fontInAss / ASS 规范一致：

- UUEncode 变体：每 3 字节编码成 4 个字符，字符值 +33（从 `!` 开始）；每行最多 80 字符；无行首长度字节、无 `end` 结束标记；尾部不足 3 字节不填充；长度正好是 60 字节倍数时不保留末尾换行。
- 每个字体条目形如：`fontname:{字体名}_{B}{I}0.ttf` + 编码数据 + 空行，其中字重 >400 加 `B`、斜体加 `I`。
- `[Fonts]` 段插在 `[Events]` 之前；如果字幕里没有 `[Events]` 段，注入会失败并按处理失败返回。
- 输出统一为带 BOM 的 UTF-8（`utf-8-sig`），兼容各种播放器对 BOM 的处理。

### 2.7 SRT 处理

- 设置页「SRT 转 ASS」默认开启：SRT 会被转成标准 ASS（`[Script Info]` + `[V4+ Styles]` + `[Events]`），默认样式名 `Default`，字体/字号/主色取设置页三项；`<i>` `<b>` `<u>` 转成 ASS 的 override 开关，`<font color="#RRGGBB">` 转成 `{\c&HBBGGRR&}`，块内换行转 `\N`。
- 主色按 ASS 的 BGR 顺序填写，例如纯白 `&H00FFFFFF`、纯红 `&H000000FF`；直接填 `#RRGGBB` 会被拼成 `&H00RRGGBB`，红蓝通道会反过来，不推荐。
- 关闭该开关后，SRT 请求原样透传，不做字体注入（适合「SRT 无所谓字体、只想减少 CPU 开销」的场景）。
- SRT 的字体/字号/主色/开关会参与字幕缓存 key，改完样式保存后旧缓存自动失效。

### 2.8 双层缓存

- 字幕缓存 key 由这些内容算出：条目 ID、媒体源 ID、字幕序号、格式、当前 Emby 地址、字体索引版本、SRT 样式版本（不含 StartPositionTicks，因为缓存的是完整字幕，裁剪在返回时逐请求做）。因此换 Emby 地址、字体库变动、改 SRT 样式都会自动失效，不需要手动清缓存。
- 内存缓存：按条数（默认 256 条）和总字节（256MB）双上限做 LRU；磁盘缓存：处理后的 ASS 存成 `.ass` 文件，默认保留 24 小时，由插件后台任务每 4 小时清理一次过期文件。
- 同一 key 的并发请求会合并成一个实际任务（single-flight），只有一个请求真正做子集化，其余等结果，避免首播时多端同时拉字幕把 CPU 打满；只有真正执行的那个请求会写盘。
- 命中缓存时日志写「字幕缓存命中（X KB，直接返回，跳过子集化）」；缓存命中同样会按请求的 StartPositionTicks 做时间窗裁剪。

### 2.9 通知、状态与日志

- **缺失字体通知**：一次请求里所有字体都失败时，按累计出现次数取前 5 名发一条消息（标题「字幕字体代理：缺失字体」）。每次插件初始化后最多发一次，避免刷屏；点「清除」缺失记录后允许再次触发（重启插件、重新初始化后也会复位）。
- **字体目录变更通知**：后台任务每 60 秒汇总一次索引变更，有变化时发消息（标题「字幕字体代理：字体索引更新」，内容含新增/修改/删除数量）。
- 两类通知都受「启用通知」开关控制；关闭后仍写日志，只是不发消息。MoviePilot 本身还需要配置可用的通知渠道，否则消息发不出去。
- **状态页**（左侧导航「状态」）：
  - 「字体索引」卡片：face 数、就绪/扫描中/未配置、fontTools 版本、uharfbuzz 版本；
  - 「反代端口」卡片：是否运行、端口号、当前回源地址；
  - 「字幕缓存」卡片：内存条数 + 磁盘文件数；
  - 「缺失字体」卡片：种类数与累计命中次数；
  - 缺失字体记录表：字体名 / 出现次数 / 最近出现时间（最多展示 200 条），可一键清除；
  - 插件日志：最近 300 行，8 秒自动刷新，可清除；有 error 级别时标题圆点变红，只有 warning 时变黄；
  - 顶部按钮：刷新、清空字幕缓存、重建字体索引（索引未就绪时重建按钮置灰）。
- **设置页**（左侧导航「设置」）：单页表单，字段顺序为：启用插件、Emby/Jellyfin 地址、回源 API Key、字体目录、SRT 兜底字体、SRT 转 ASS 字号、SRT 转 ASS 主色、SRT 转 ASS、处理结果缓存、缓存有效期、子集化并发上限、处理失败时返回原始字幕、启用内置反代端口、内置反代端口、启用通知，底部「保存配置」。
- 插件停用时，除设置页之外的页面会盖一层「插件已停用」遮罩，并提示前往设置启用。

## 三、安装与启用

### 3.1 版本说明

- V3 版：**3.1.2**。本插件只提供 V3 版（仓库根 README 的 V2 栏为「-」）。
- 适用 MoviePilot V3，插件声明 `system_version >= 3.0.0`；需要 Python ≥ 3.10（MoviePilot V3 镜像通常满足）。
- 宿主导入使用 V3 稳定 SDK（`app.sdk.logging` / `app.sdk.config`），因此不能装到 MoviePilot V2。

### 3.2 安装步骤

1. 打开 MoviePilot → 插件市场（第三方插件 / 插件仓库）；
2. 添加仓库地址：`https://github.com/LXT-A-X/MoviePilot-Plugins`；
3. 搜索「字幕字体代理」（插件 ID：`FontInAssProxy`）；
4. 安装，版本选择 **3.1.2**；
5. 安装完成后在插件列表打开本插件；
6. 进入左侧「设置」，按「七、首次配置流程」逐项填写；
7. 打开「启用插件」并保存，等待状态页显示字体索引就绪。

### 3.3 首次安装会自动做什么

- 插件启动时后台检查依赖：fontTools（要求 ≥4.55，低于该版本会自动升级）、watchdog、cachetools、httpx、charset-normalizer、uharfbuzz、websockets。缺失的会用 pip 安装，日志写「依赖检查：需要安装/升级 ...」「依赖安装完成: ...」。
- 自动安装跑在后台线程，不阻塞启动。如果宿主环境禁止 pip 安装，日志会写「依赖安装失败: ...」或「依赖自动安装异常: ...」，需要手动在容器内安装依赖。
- 如果「字体目录」已配置，会立刻开始后台全量扫描并建索引；首次扫描耗时取决于字体数量和磁盘性能，上万字体通常需要几分钟。

### 3.4 升级

- 在插件市场点更新到 3.1.2，更新后重新启用/重启一次插件，让运行时与索引按新配置重建。
- 索引结构升级会自动重建；升级后首次启动会重新扫描字体目录。
- 从 3.0.x 升级到 3.1.x：内置反代仍是唯一入口；如果之前按老教程在 nginx 里做了 `/subtitle` 转发，可以去掉，改为客户端直连 8097（或继续让 nginx 转发到 8097）。
- 升级不会删除你的字体库和媒体库文件；插件数据目录中的索引与缓存可能被重建。

## 五、接入方式：内置反代端口（当前唯一入口）

### 5.1 工作方式

- 插件进程内起一个独立 HTTP 服务，监听 `0.0.0.0:端口`（默认 8097），后台线程运行自己的事件循环，与 MoviePilot 主循环隔离。
- 客户端把「Emby 服务器地址」从 `http://<Emby地址>:8096` 改成 `http://<MoviePilot地址>:8097`，之后所有请求先到插件，再由插件转发给 Emby。
- 字幕请求被处理并注入字体；其他请求（视频、图片、Web、API、WebSocket）原样透传。
- 停止/重启插件时，反代会先等待端口真正释放（最多 12 秒）；启动失败会退避重试 4 次（0.5s / 1s / 1.5s），减少「重启后反代彻底下线」的情况。
- 启动成功日志：`内置反代已监听 0.0.0.0:8097`；端口被占用日志：`内置反代启动失败（端口 8097 可能被占用）`。

### 5.2 端口映射

- Docker 部署：容器端口映射里加一条 `8097:8097`（或你自定义的端口），然后重启容器。
- 只映射容器端口还不够：宿主机防火墙、路由器、NAS 安全组也要放行同一端口。
- 端口只在启用开关并保存后才监听；「启用内置反代端口」默认是关闭的。

### 5.3 客户端设置

- 手机/电视/平板上的 Emby/Jellyfin 客户端：把服务器地址改为 `http://<MoviePilot 所在主机地址>:8097`，重新登录即可。
- 如果客户端原来使用 `http://<Emby地址>:8096/emby` 这种带路径前缀的地址：反代能识别带前缀的字幕路径；「Emby/Jellyfin 地址」只填站点根地址（不要重复带 `/emby`），否则会拼成两段前缀导致回源 404。
- 使用 HTTPS 的 Emby：回源按普通 HTTPS 校验证书，自签名证书会失败（见 FAQ Q12）；内置反代本身是 HTTP，建议只在局域网使用；需要 HTTPS 时可在 8097 前自行加一层带证书的反向代理。
- 关掉「启用插件」或「启用内置反代端口」前，请先把所有客户端地址改回 Emby 原地址，否则客户端会直接连不上（设置页开关提示原文：关闭后反代端口与处理链路全部停止）。

### 5.4 如何确认接入成功

1. 状态页「反代端口」卡片显示端口号（绿色），下方显示当前回源地址；
2. 插件日志出现「内置反代已监听 ...」；
3. 播放一条带特效字幕的视频，日志按顺序出现：`字幕URL:` → `ass分析` → `从本地加载字体` → `子集化 N 个字符` → `子集化嵌入` → `字幕处理完成: X MB ==> Y MB`；
4. 浏览器开发者工具里，字幕请求的响应头含 `X-FontInAss: 1`；
5. 画面上特效字幕字体正确（与原字幕组预期一致），换一台没装字体的设备也一样。

## 六、配置项详解

> 默认值取自插件内置默认配置（`_DEFAULT_CONFIG`）与设置页默认值，两处一致。修改后保存立即热生效（会重启反代、启动新的索引扫描），不需要重启 MoviePilot。

### 6.1 总开关

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用插件 | `enabled` | 开启 | 关闭后插件不初始化：内置反代停止监听、字幕处理链路停止，客户端指向反代端口会直接连不上。仅用于彻底停用插件。 |

### 6.2 回源（Emby / Jellyfin）

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| Emby/Jellyfin 地址 | `emby_url` | 空 | 回源根地址，例如 `http://<Emby地址>:8096`。末尾不要带 `/`，也不要带 `/emby` 路径前缀（客户端请求里的前缀会原样拼在后面）。不填则无法回源，日志警告「未配置 Emby 地址，处理将无法回源」。 |
| 回源 API Key | `emby_api_key` | 空 | 留空时原样转发客户端请求里的 `api_key` / `X-Emby-Token`；填写后会用它覆盖请求 query 里的 `api_key` 与 `X-Emby-Token`。适用于「客户端 key 没有字幕权限」或「统一用管理员 key 回源」的场景。属于敏感信息，见第十章。 |

### 6.3 字体库与兜底字体

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 字体目录 | `font_dirs` | 空 | 字体库目录（容器内路径），多个用英文分号 `;` 分隔，递归扫描；目录必须挂载进 MoviePilot 容器。目录不存在会被静默忽略，全部无效时索引为空、字幕一律透传。 |
| SRT 兜底字体 | `srt_default_font` | 思源黑体 CN | 两种用途：① SRT 转 ASS 时作为默认样式字体；② ASS 字幕里的字体匹配失败时，用这个字体替换显示（按 400 字重、非斜体匹配）。建议填字体库里确实存在的字体名，否则兜底也会失败。 |

### 6.4 SRT 相关

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| SRT 转 ASS | `srt_to_ass_enabled` | 开启 | 开启：SRT 转成 ASS 并注入字体；关闭：SRT 原样透传，不做任何处理（省 CPU）。 |
| SRT 转 ASS 字号 | `srt_font_size` | 20 | 转出来的 ASS 样式字号；填非数字会回退为 20。 |
| SRT 转 ASS 主色 | `srt_primary_colour` | `&H00FFFFFF` | ASS 的 BGR 颜色值（注意是 BGR 不是 RGB）；纯白 `&H00FFFFFF`，纯红 `&H000000FF`，纯蓝 `&H00FF0000`。建议保持 `&H` 开头。 |

### 6.5 缓存与性能

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 处理结果缓存 | `cache_enabled` | 开启 | 内存 LRU + 磁盘双层缓存。关闭后每次播放都实时子集化，CPU 占用和首播延迟都会上升；运行中的缓存实例会被释放。 |
| 缓存有效期（小时） | `cache_ttl_hours` | 24 | 磁盘缓存（`.ass` 文件）保留时长；插件后台任务每 4 小时清理一次过期文件。填 0 表示不按时间过期，只能手动清空。 |
| 子集化并发上限 | `max_concurrent_subset` | 4 | 同时进行的子集化任务数；线程池大小为其 2 倍。小于 1 会被强制为 1，非数字回退 4。调大能提升多端同时首播的吞吐，但会占用更多 CPU，低配设备不建议超过 4。 |

### 6.6 失败策略

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 处理失败时返回原始字幕 | `passthrough_on_error` | 开启 | 开启：处理失败（回源失败、编码识别失败、解析失败、字体全缺、注入失败等）时返回原始字幕，播放不中断，只是没有内嵌字体。关闭：失败直接返回 HTTP 500（正文 `subtitle processing failed`）。注意：实现上「跳过处理」与「处理失败」共用同一条返回路径，关闭后连「字幕已含 `[Fonts]` 跳过」「索引未就绪」也会返回 500，因此正常使用请保持开启，只在定位问题时临时关闭。 |

### 6.7 内置反代

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用内置反代端口 | `internal_proxy_enabled` | 关闭 | 打开后插件在指定端口监听，作为字幕处理入口；需要在容器上映射该端口。关闭时插件不监听任何端口（只保留状态/设置页和后台索引）。 |
| 内置反代端口 | `internal_proxy_port` | 8097 | 监听端口，能否被外部访问取决于你的映射；非数字会回退 8097。端口被占用时启动失败并重试 4 次，日志提示「内置反代端口 8097 启动失败（重试 4 次仍无法监听）」。改端口后记得同步改容器映射和客户端地址。 |

### 6.8 通知

| 设置项 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用通知 | `notify_enabled` | 开启 | 控制「缺失字体」与「字体索引更新」两类消息。关闭后仍写日志、仍更新索引，只是不发通知；MoviePilot 自身还需要配置可用的通知渠道，否则消息发不出去。 |

### 6.9 未在界面暴露的配置项

插件实现里还读取一个 `cache_dir`（缓存目录，默认在插件数据目录下的 `cache` 子目录）。设置页没有提供这个字段，普通用户不需要关心；只有特殊部署（想把缓存放到别的挂载盘）时才会通过配置直接写入。

### 6.10 保存配置时发生了什么

- 配置会写入 MoviePilot 的插件配置（重启后保留），然后立即重建运行时：停掉旧的反代/索引/线程池 → 按新配置重建字体索引（后台扫描）→ 重建缓存实例 → 重新启动内置反代。
- 保存成功提示「配置已保存并生效（字体索引后台扫描中…）」；插件被关闭时提示「配置已保存（插件已禁用）」；运行时启动异常时提示「配置已保存，但运行时启动失败: ...」。
- 保存会清空内存缓存、重新全量扫描索引（磁盘缓存文件仍在，索引版本变化会让旧缓存失效），因此保存后第一次播放可能稍慢。

## 七、首次配置完整流程

### 步骤 1：准备字体库

- 在 NAS 或宿主机上准备字体目录（可以多个），确保已挂载到 MoviePilot 容器内的某个路径（docker-compose 的 volumes 或 `-v`）。
- 字体建议按「厂商 / 格式 / 名称」整理，但插件不要求目录结构，递归扫描即可。
- 尽可能补齐字幕组常用的字体（思源系列、方正系列、华康/蒙纳系列、日系明朝/黑体等），缺得越少，兜底替换越少。

### 步骤 2：确认网络

- 在 MoviePilot 容器内确认能访问 Emby 地址（例如用容器内 curl/wget 访问 Emby 首页）；容器网络不通时，后续一切都会失败。

### 步骤 3：打开设置页填回源

- 「Emby/Jellyfin 地址」：填 `http://<Emby地址>:8096`（结尾不要 `/`）。
- 「回源 API Key」：多数情况留空，客户端用管理员账号时也不需要；只有回源 401/403 时才考虑填写。

### 步骤 4：填字体目录与兜底字体

- 「字体目录」：多个目录用 `;` 分隔，填容器内路径。
- 「SRT 兜底字体」：填字体库中确实存在的字体名，推荐「思源黑体 CN」（如果库里没有，改成你库里有的黑体字族名）。

### 步骤 5：按需调整 SRT 与性能

- 如果主要看 ASS 特效字幕，SRT 相关保持默认即可；如果服务器性能弱，可把「子集化并发上限」降到 2。

### 步骤 6：启用内置反代

- 打开「启用内置反代端口」，端口保持 8097（或改成你要用的端口）。
- 在容器配置里映射该端口，重启容器让映射生效。

### 步骤 7：保存并等索引

- 点「保存配置」。
- 到状态页看「字体索引」卡片：先是「扫描中… 已 N 个字体」，扫描完成后变「就绪 · fontTools x.y.z · uharfbuzz x.y」。
- 字体很多时耐心等待；期间播放不受影响（未就绪时字幕透传）。

### 步骤 8：客户端切到反代地址

- 在所有播放设备上把 Emby 服务器地址改成 `http://<MoviePilot 主机地址>:8097`。
- 如果客户端支持多地址，建议保留原 Emby 地址作为备份，便于排障时切回。

### 步骤 9：播放验证

- 播放一集带特效字幕的剧（最好选字幕字体较特殊的那集）。
- 看状态页「插件日志」是否有完整的处理链路日志。
- 看画面字体是否正确；对比直连 Emby 时的显示效果。

### 步骤 10：按需处理缺失

- 状态页「缺失字体记录」出现名字时，说明字幕引用了库里没有的字体（或匹配不上的别名）。
- 把对应字体加入字体库 → 等待自动索引（watchdog 立即、轮询最多 60 秒）→ 再播一次；必要时点「重建字体索引」。
- 处理完可点「清除」清空缺失记录，便于下次重新统计。

## 八、典型场景

### 场景 1：电视 / 投影没装字体，特效字幕变方块

**痛点**：客厅电视只认系统自带字体，字幕组用的字体一个都没有，字幕显示成方块；在电视上装字体非常麻烦。

**做法**：按第七章配好字体库和内置反代，把电视上的 Emby 地址改成反代端口。播放时插件在服务端完成子集化和内嵌，电视拿到的是「自带字体」的字幕。

**预期**：状态页日志出现完整处理链路；画面字体与字幕组预期一致；即使电视里一个第三方字体都没有，也能正常显示。

### 场景 2：全家多台设备共用一套字体库

**痛点**：手机、平板、电视、投影各装一遍字体不现实，字体版本还容易不一致。

**做法**：字体只放在 NAS/宿主机一份，挂载给 MoviePilot；所有客户端都指向同一个反代端口。新增字体放进目录后，索引自动更新，全部设备立即受益。

**预期**：状态页「字体目录变更」日志与通知出现新增数量；无需逐台设备操作。

### 场景 3：只有 SRT 字幕的剧集

**痛点**：SRT 没有字体信息，默认由播放器决定字体，有时显示效果很差。

**做法**：保持「SRT 转 ASS」开启，设置合适的「SRT 兜底字体」/字号/主色。插件会把 SRT 转成 ASS 并注入字体。

**预期**：日志显示 SRT 请求也走完整处理链路；画面字体、字号、颜色符合设置。如果只想省 CPU，可关闭该开关让 SRT 原样透传。

### 场景 4：新字体入库后自动生效

**做法**：把字体文件复制到字体目录；watchdog 会增量入库（不可用时最多 60 秒轮询）；索引版本变化会让字幕缓存自动失效。

**预期**：状态页日志「字体目录变更：新增 文件名」；稍后重播即可用上新字体；也可在状态页点「重建字体索引」强制全量刷新。

### 场景 5：Emby 换地址 / 迁移

**做法**：在设置页改「Emby/Jellyfin 地址」并保存；客户端地址不用动（仍指反代端口）。缓存 key 包含 Emby 地址，会自动失效。

**预期**：日志显示新的回源地址；旧缓存不会串用。如果仍有异常，点「清空字幕缓存」。

### 场景 6：排障时临时绕过插件

**做法**：把客户端地址临时改回 Emby 原端口，直接对比「直连」与「经反代」的差异；或临时关闭「处理失败时返回原始字幕」来确认问题是否出在插件处理（确认后立即恢复）。

**预期**：能快速区分是播放器/字幕本身的问题，还是插件处理链路的问题。

### 场景 7：Emby Web 端的会话与遥控

**做法**：保持内置反代开启，插件会透传 `/embywebsocket`、`/socket`；确保容器装了 websockets 库（插件依赖检查会尝试安装）。

**预期**：Web 端播放进度同步、遥控操作正常；若 WebSocket 不可用，只影响实时会话，不影响播放与字幕。

## 九、与其他组件的联动

### 9.1 MoviePilot 插件框架

- **后台服务任务 2 个**：
  - `FFA 字体变更通知`：每 60 秒消费一次索引变更统计，有新字体/修改/删除时写日志并按开关发通知；
  - `FFA 缓存清理`：每 4 小时（14400 秒）清理一次过期的磁盘字幕缓存。
- **消息通知**：通过 MoviePilot 的 `post_message` 发送到系统通知渠道（需要 MoviePilot 已配置通知渠道）。
- **管理接口**（全部要求登录 Bearer，路径前缀 `/api/v1/plugin/FontInAssProxy`）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/config` | 读取当前配置 |
| POST | `/config` | 保存配置并热生效 |
| GET | `/status` | 运行状态（索引/缓存/反代/版本/缺失统计） |
| GET | `/logs` | 读取插件日志（默认 300 行） |
| POST | `/logs/clear` | 截断插件日志文件 |
| GET | `/missing` | 缺失字体列表（按次数降序，最多 200 条） |
| POST | `/missing/clear` | 清除缺失记录 |
| POST | `/rebuild` | 重建字体索引 |
| POST | `/clear_cache` | 清空字幕缓存 |

- **页面**：Vue 联邦页面，向宿主暴露 `Page`（状态/设置容器）与 `Config`（设置页组件）；插件详情页即本插件页面。
- **不注册 Telegram 命令**（3.0.2 起明确不提供，命令列表为空）；**没有仪表盘组件**。

### 9.2 Emby / Jellyfin

- 只通过 HTTP 回源读取：字幕接口、媒体流、Web/API/WebSocket；不改 Emby 数据库、不写元数据、不触发刮削、不删除任何内容。
- 对 Emby 的要求就是「同一个地址能被 MoviePilot 容器访问」；Jellyfin 的接口路径与 Emby 兼容，同样适用。
- 插件不依赖 Emby 端的插件或扩展，也不要求 Emby 开启特殊选项。

### 9.3 下载器 / 整理 / 其他插件

- 与下载器、MoviePilot 整理入库、Emby 通知等都没有联动：它是纯「播放期」的字幕代理，下载、整理、刮削流程都不经过它。
- 不订阅 MoviePilot 的入库/整理等事件（代码中没有事件响应逻辑），也不会触发扫描或写媒体库。
- 与「字体分类管家」互补：可以用字体分类管家维护字体库，本插件直接指向同一个字体目录即可。建议避免在播放高峰时大量写入字体目录（watchdog 会逐文件增量解析）。

### 9.4 外部反代 / CDN

- 内置反代是普通 HTTP 服务，可以在它前面再加 nginx/Traefik 做 HTTPS、域名、基础认证；插件不感知，也不会与之冲突。
- 不建议把 8097 直接暴露到公网（见第十章）。

## 十、安全与权限

### 10.1 访问控制

- 插件 `auth_level = 2`，即插件页面与所有管理接口仅管理员可用；接口统一 `auth: bear`，未登录访问会被拒绝。
- 反代端口本身没有额外的插件级鉴权：它把请求转发给 Emby，由 Emby 自己的 api_key/token 校验。也就是说「能访问 8097 的人，等于能访问你的 Emby」。
- 因此：**只在局域网内使用**；不要把 8097 映射到公网；如果必须公网使用，请在前面加带强认证的反向代理（HTTPS + 认证），并限制来源 IP。
- 反代监听 `0.0.0.0`，会对容器所在网络的所有接口开放；云服务器/多网卡环境要配合安全组。

### 10.2 敏感信息

- 「回源 API Key」以插件配置形式保存在 MoviePilot 中（插件本身不做额外加密），能打开插件设置页的管理员都能看到；建议使用权限最小、可随时吊销的 key。
- 插件日志会记录完整字幕 URL（`字幕URL: ...`），其中可能包含客户端自带的 api_key；把日志贴给别人排障前请先脱敏。
- 回源失败日志会打印回源 URL，同样可能带 query 中的令牌。
- 不要在截图/日志里暴露 Emby 管理员 token、Cookie 或内网地址。

### 10.3 读写边界

- **只读**：字体目录（只打开读取，不写不改不删）、媒体库（完全不动）、Emby（只发 HTTP 请求）。
- **写入**：插件数据目录（字体索引 SQLite 库及 WAL 文件、字幕缓存 `.ass`、运行数据）、插件日志文件。
- 清空字幕缓存：只删除缓存目录下的 `.ass` 文件。
- 清除插件日志：只截断本插件日志文件（文件保留为空）。
- 清除缺失字体记录：只清内存统计，不影响索引和字体文件。
- 重建字体索引：只删索引表并重新扫描，不碰字体文件；重建期间字幕请求透传。
- 卸载插件：插件数据目录与日志不会由插件自动删除，可自行清理，不影响系统。

### 10.4 危险操作提示

- 关闭「启用插件」，或在客户端仍指向 8097 时关闭内置反代 → 客户端直接断连，需先把地址改回 Emby 原地址。
- 修改反代端口后忘记改容器映射/客户端 → 表现为「连不上」。
- 关闭 `passthrough_on_error` → 一旦处理失败（包括正常的跳过）返回 500，播放器可能不显示字幕。
- 清空缓存 / 重建索引 → 短期内首次播放变慢；重建期间的请求不注入字体。
- 把 `max_concurrent_subset` 调得过高 → 多端同时首播时 CPU 打满，反而影响 MoviePilot 其他功能。

## 十一、数据、缓存与清理

- **插件数据目录**：
  - `fontindex.db`（以及 SQLite WAL 临时文件）：字体索引库，大小随字体数量增长；
  - `cache/`：字幕缓存 `.ass` 文件（可通过 `cache_dir` 改位置，设置页不暴露）。
- **日志**：插件优先写独立的插件日志文件（日志目录下 `plugins/fontinassproxy.log`）；状态页读取时优先读它，读不到再从 MoviePilot 主日志里筛选本插件行。
- **清理方式**：
  - 字幕缓存：状态页「清空字幕缓存」，或等 TTL（默认 24 小时）与每 4 小时的自动清理；
  - 索引：状态页「重建字体索引」（需要时间，建议空闲时操作）；
  - 日志：状态页「插件日志 → 清除」；
  - 磁盘紧张时优先清缓存，索引重建成本较高。
- **缓存文件体积**：处理后的 ASS 内含内嵌字体，通常明显大于原字幕；日志里的「X MB ==> Y MB」就是体积变化，可用来判断是否字体内嵌过多。

## 十二、常见问题 FAQ

### Q1：状态页「字体索引」显示「未配置字体目录」或一直是红色

原因：`font_dirs` 为空；或填的路径在容器内不存在（插件只接受真实存在的目录，不存在的会被忽略）。

排查与处理：确认设置页字体目录非空；确认路径是容器内路径且已挂载；确认目录里有 ttf/otf/ttc/otc 文件。修正后保存，看日志是否出现「字体索引启动，目录: [...]」和「字体索引就绪: N 个 face」。

### Q2：状态页显示「uharfbuzz 未安装（fontTools 兜底）」

原因：uharfbuzz 没装成功（宿主禁止 pip、镜像缺编译依赖等）。

影响：仍能工作，但子集化慢很多（大字体可能从几十毫秒变一秒以上），并发时更容易降级透传。

处理：容器内手动安装 `uharfbuzz>=0.40.0` 后重启插件；安装后再看状态页版本号是否出现。

### Q3：客户端连不上 8097

逐项检查：启用插件；启用内置反代端口；端口映射；宿主机防火墙/安全组；客户端填的是 MoviePilot 地址而不是 Emby 地址；端口没被别的程序占用（日志「内置反代启动失败（端口 8097 可能被占用）」或「内置反代端口 8097 启动失败（重试 4 次仍无法监听）」）。

验证：状态页「反代端口」显示端口号；换设备/换网络试；用浏览器访问 `http://<MoviePilot地址>:8097` 应能看到 Emby 登录页（说明反代与回源都通了）。

### Q4：字幕还是乱码 / 方块

按顺序排查：

1. 确认播放器确实连的是反代端口（响应头有没有 `X-FontInAss: 1`）；
2. 看状态页日志是否有「字幕处理完成」；没有则是请求没走处理链路（路径不匹配 / 未启用 / 索引未就绪 / 已有内嵌字体跳过）；
3. 看「缺失字体记录」：字幕引用的字体不在库里；
4. 字体在库里但仍缺失 → 可能名字差异大（繁体名、拼音名、日文名、厂商前缀），把缺失名字加进字体库或换同族字体后重试；仍不行就点「重建字体索引」再试；
5. 确认兜底字体「思源黑体 CN」在库里存在，否则兜底也无效；
6. 若命中缓存且字体/配置刚改过，点「清空字幕缓存」后重播。

### Q5：缺失字体列表里有名字，但库里明明有这个字体

原因：字体内部名与字幕写的名字不完全一致（常见于华康/日系字体的 W5/W7、Std/Win/GB/B5 中缀，或繁体名、别名未收录）。

处理：先升级到 3.1.2（3.1.1 已优化切词与字重惩罚）；确认同一字族的其它字重文件是否在库里（文件名匹配也能命中）；可把字体文件重命名成字幕里写的名字再放入库（文件名会作为别名参与匹配）；最后再点「重建字体索引」。

### Q6：播放卡顿、起播慢，日志有「子集化并发已满，请求降级透传」

原因：同时首播的请求超过并发上限，等待 3 秒仍拿不到许可，本次请求直接返回原字幕（没有内嵌字体）。

处理：适当提高「子集化并发上限」（注意 CPU 余量）；确认 uharfbuzz 已安装；确认字体文件不要放在很慢的网络盘；错开多端同时首播。

### Q7：关闭「处理失败时返回原始字幕」后播放器没字幕 / 报错

这是预期行为：关闭后处理失败返回 500，并且「跳过处理」（已有 `[Fonts]`、索引未就绪等）也会走同一条失败路径返回 500。

处理：保持开启；只在定位「到底是不是插件处理失败」时临时关闭，定位完立即恢复。

### Q8：SRT 字幕没被处理

检查：「SRT 转 ASS」是否开启；字幕格式是否是 `.srt` / `.subrip`（VTT 等其它格式不处理）；索引是否就绪；是否命中了已含 `[Fonts]` 的跳过逻辑（正常 SRT 不会有）。

开启后仍无效时看日志是「字幕编码无法识别」还是「字体索引未就绪」。

### Q9：日志里出现「字幕已含 [Fonts] 内嵌字体，跳过处理（原样透传）」

这是正常逻辑：该字幕已经内嵌过字体（可能由其它工具处理过），插件不重复加工。若你希望强制重新生成，需要先换用未内嵌的原始字幕，插件不提供「强制重做」开关。

### Q10：播放暂停 30 秒左右视频断流

该问题在 3.1.0 已修复（视频流式透传不再使用 30 秒读超时）；如果你仍在旧版本，请升级。字幕回源仍有 30 秒超时，正常字幕请求不会触发。

### Q11：Emby Web 端会话不同步、遥控失效

内置反代对 `/embywebsocket`、`/socket` 做 WebSocket 透传，需要 `websockets` 库；缺失时 WebSocket 会被拒绝（插件日志可能出现「WebSocket 透传异常」），只影响 Web 端实时会话，不影响播放与字幕。

处理：确认依赖已安装（插件启动时会检查），重启插件；仍不行时直接用客户端播放。

### Q12：HTTPS + 自签名证书的 Emby 回源失败

回源使用标准 HTTPS 证书校验，插件没有「跳过证书校验」的开关；自签名/过期证书会失败，日志出现「回源失败 ...」。

处理：给 Emby 换受信任证书；或局域网内改用 HTTP 地址；或在两者之间加一层证书正确的反向代理。

### Q13：换了 Emby 地址后仍拿到旧字幕 / 旧字体效果

缓存 key 已包含 Emby 地址与索引版本，正常会自动失效；如果仍异常，点「清空字幕缓存」；确认保存配置后插件已重建运行时（设置页提示「配置已保存并生效」）。

### Q14：重建索引时字幕没有内嵌字体

预期行为：重建期间索引标记未就绪，所有字幕请求透传，避免读到残缺数据。重建完成后自动恢复；字体多时建议在没人看片时操作。

### Q15：插件日志是空的

状态页日志来自独立插件日志文件；如果文件不存在，会退而读取 MoviePilot 主日志里含插件名的行。日志为空通常表示还没有任何本插件日志写入（例如插件刚启用、还没播放、日志被清空）。播放一次带字幕的视频后再刷新。

## 十四、已知限制

- 只处理 ASS/SSA 与（可选的）SRT；VTT、SUB 等格式不处理。
